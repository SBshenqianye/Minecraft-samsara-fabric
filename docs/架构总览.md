## 1. 模块图

```
                         ┌──────────────────────────────┐
                         │  web/  (HTTP 外层)            │
                         │  LocalWebServer / *WebService │
                         └──────────────┬───────────────┘
                                        │ 只向下调用
        ┌───────────────┬───────────────┼────────────────┬──────────────┐
        ▼               ▼               ▼                ▼              ▼
   season/          claim/          lottery/        insurance/      container/
   周目/世界栈       圈地/几何        乐透/基金        保险            容器/背包
        │               │               │                │              │
        └───────────────┴───────┬───────┴────────────────┴──────────────┘
                                ▼
                    storage/StoragePaths（唯一路径入口）
                                │
                                ▼
                    config/（配置）/ world/（存档）/ serverRoot/samsara（共享）
```

依赖方向固定为 **web → service/domain → storage/config**：

- 领域包之间可以互相调用（season ↔ claim ↔ container 等），但不得 `import ...web.*`。
- `storage` 只依赖根入口 `Samsara` 与 `config`。
- `web` 可以 import 任何领域包；反向调用必须加接口，在 `Samsara.onInitializeServer` 装配。

守卫：`ArchitectureGuardTest`（`gradle test` 执行）覆盖“配置根/备份根只能 StoragePaths 拼”“领域包不 import web”“storage 不越层”。

## 2. 数据流

### 玩家命令

```
Minecraft 命令 → command/ → domain service → 内存状态 + JSON/YAML 落盘
                                   └→ output/ 渲染（模板可由 Web 编辑）
```

### Web 请求

```
浏览器 → LocalWebServer
        → authorize()：Bearer token → AgentAuthService（scope/限流/幂等）
        → WebAuditService.capture()
        → 按路径路由到 *WebService → 领域服务
        → WebHttp.json 统一响应/缓存/CSP
```

### 跨周目数据

- 奖池/保险基金：`<serverRoot>/samsara/shared/lottery|insurance`，**不随世界切换**。
- 身份组/背包：`world/samsara/identity`，固定跟随主存档。
- 圈地/轨迹/地图/容器：`world/samsara/*`，随各自周目/世界栈层保留。
- 备份：`<serverRoot>/backups/samsara/`；本体备份 = world + config/samsara + shared。

## 3. 存储布局

| 根 | 解析入口 | 内容 | 换周目 | 进本体备份 |
|---|---|---|---|---|
| `config/samsara` | `StoragePaths.configRoot()` / `configDirAt()` | 可手改配置 YAML、web.yml | 保留 | 进 |
| `world/samsara` | `StoragePaths.worldDataRoot()` | 圈地、轨迹、地图、容器、当前周目 | 随世界 | 进 |
| `<server>/samsara/shared` | `StoragePaths.sharedDataRoot()` | 奖池/基金/保险基金 | **保留滚存** | 进 |
| `<server>/samsara` | `StoragePaths.serverDataRoot()` | `shared/` 的父目录 | 保留 | 只备份 shared |
| `<server>/backups/samsara` | `StoragePaths.backupsRootAt()` | 本体/世界栈/删除/配置备份 | 保留 | 不适用 |

## 4. 扩展点

| 需求 | 落点 | 不要做 |
|---|---|---|
| 新增 Web API | `web/*WebService` + `LocalWebServer` 路由 + `ApiScope` scope | 不要直接 `fetch` 前端、不要把业务写进 handler |
| 新增页面 | `web-src/src/pages/<page>/` + `router.js` + `WebSecurity.staticResource` | 不要改 `AdminLayout` 加页面 `v-if` |
| 新增领域数据 | 先在 `StoragePaths` 加方法，再写 `StorageMigration` 迁移 | 不要硬编码 `config/samsara`、`backups/samsara` |
| 新增输出消息 | `output/OutputCatalog` 注册模板 + 字段变量；保留 `{message}` 兼容 | 不要只拼一整段字符串 |
| 新增备份内容 | `ServerBackup.createZip/executeRestore`，同步更新预览/回滚 | 不要只备份 world 而漏掉 shared |

## 5. 守卫映射（AGENTS.md → 可执行检查）

| 约束 | 守卫 |
|---|---|
| 配置根只能 `StoragePaths` | `ArchitectureGuardTest.onlyStoragePathsReadsFabricConfigDir/SpellsConfigDirectory` |
| 备份根只能 `StoragePaths` | `ArchitectureGuardTest.onlyStoragePathsSpellsBackupDirectory` |
| 本体备份必须含 `shared` | `ArchitectureGuardTest.serverBackupIncludesCrossSeasonSharedData` + `ServerBackupTest` |
| 领域包不得 import `web` | `ArchitectureGuardTest.domainPackagesDoNotImportWebLayer` |
| `storage` 不越层依赖 | `ArchitectureGuardTest.storagePackageOnlyDependsOnConfigAndEntrypoint` |
| 前端不得回退旧内核/直接 fetch/innerHTML | `tools/agent/check-framework.mjs`（`npm run check`） |
| 路由必须进静态白名单 | `tools/agent/check-routes.mjs`（`npm run check`） |

## 6. 类型化响应（进行中）

已把两个高频只读接口从 `Map<String,Object>` 换成 record，JSON 字段名保持不变：

- `GET /api/status` → `web/ServerStatus.java`（含 `configFiles` 嵌套 record）
- `GET /api/user/status` → `web/UserStatus.java`
- `GET /api/storage` → `StorageLayoutWebService.StorageLayout` / `Row`
- `GET /api/audit` → `AuditPage`

其余业务接口仍以 Map 组装；迁移时按“一个域一个提交”，先补 `ServerStatusTest` 这类字段名回归测试，避免前端契约漂移。

拆分原则：先补 characterization test，再搬代码；每刀只搬一个职责，行为不变。
