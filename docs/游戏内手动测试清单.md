# 游戏内手动测试清单

> 用途：所有“只能在 Minecraft 客户端里确认”的验收都登记在这里。
> 你统一挑时间进服测试；我没有 computer use 之前不会假装这些已验完。
>
> 测试服优先（`test-server`，游戏端口 25566，Web 8722）；生产只在你明确要求时做，
> 且测试前先确认没有其他玩家在关键区域。

## 测试前准备

1. 启动测试服，确认 Web `/api/status` 正常。
2. 给自己 OP：控制台 `op <你的ID>`。
3. 准备材料：白色旗帜若干、任意染料、TNT、打火石、活塞、方块。
4. 测试完把结果填到文末“记录”，或直接告诉我哪条失败 + 截图/日志时间。

## 1. 墙挂旗帜算圈地（T-08）

**目的**：墙旗与立式旗一样能注册圈地、显示距离、拆除后注销。

1. 在墙上贴一面带方向图案的旗帜（例如 `stripe_left` + 橙色）。
2. 空手右键这面墙旗。
3. 期望：聊天/动作栏显示 `[圈地旗] 区块 … ✓ 受保护 · 主人 …`，并出现边界粒子。
4. 用非主人账号右键/拆除，期望被拒绝；主人拆除后，`claims.json` 对应节点消失。
5. 记录：旗面朝向、显示的距离、粒子范围是否和实际保护一致。

## 2. 爆炸/活塞/命令拆旗后注销圈地（R-02）

**目的**：非玩家方式移除旗帜后，不再留下“看不见的保护”。

1. 放一面圈地旗，右键确认 `✓ 受保护`。
2. 分别测试：
   - TNT 在旗帜旁引爆；
   - 活塞把旗帜推掉/推走；
   - 控制台 `/setblock <x> <y> <z> air`；
   - `/fill` 清掉一片包含旗帜的方块。
3. 每种方式后等 1 秒，右键原位置附近方块。
4. 期望：`claim info` 不再显示该区块受保护；`world/samsara/claims/claims.json` 里对应节点消失。
5. 换另一个账号在同一位置重新放旗：期望显示新主人，旧主人不能拆这面新旗。

## 3. 旧栈层死亡重生（R-03）

**目的**：在旧世界玩的玩家死亡后留在旧层，不被原版回退到顶层。

1. 用世界栈命令进入 `stack_0`（旧层）。
2. `kill @s` 或落岩浆死亡。
3. 期望：重生后仍在 `stack_0`；聊天不出现异常提示。
4. 如果出现“已把你放回死亡所在层的世界出生点”，说明原版回退被纠正，也是通过。
5. 查 `logs/latest.log`：不应出现“重生点却落在顶层”的反复刷屏。

## 4. 开新周目自动结束（R-05）

**目的**：`/season create` 不再要求先 `/season end`，且任何时刻只有一个 ACTIVE。

1. 确认当前有一个 ACTIVE 周目（`/samsara season status`）。
2. 执行 `/samsara season create 测试周目 same-world`。
3. 期望：返回“已创建周目 … PENDING”，同时旧周目变为 ENDED；`/samsara season status` 不出现两个 ACTIVE。
4. 测完用 `/samsara season end` 或删除测试周目，恢复原状。

## 5. 乐透退款播报（R-04）

**目的**：取消/统计不完整时，游戏内播报是“已退款、奖池不滚存”，不是“奖池滚入下一轮”。

1. 在测试服制造至少一张下注（可用假玩家或自己）。
2. 管理员执行 `/samsara lottery cancel`，按提示再执行一次确认。
3. 期望：
   - 全服播报含“本轮退款…奖池不滚存”；
   - 下注物品回到背包或待领取；
   - 历史列表显示“已退款”。
4. 记录播报原文。

## 6. 公告渲染（颜色/变量/位置）

**目的**：中文、颜色码、变量在游戏内正常，不是 `?` 或原样输出。

1. Web 公告页编辑一条聊天公告：
   `&e[公告] &f欢迎 {player} 来到服务器！\n&7在线 {online} 人 · {world}`
2. 点“发送”或让玩家上线触发。
3. 期望：颜色生效、变量被替换、中文正常、没有 `{player}` 这类未替换文本。
4. 再测 ActionBar / Title / BossBar 各一次（可选）。

## 7. 圈地右键粒子预览（T-01 遗留）

**目的**：右键预览范围与实际保护一致。

1. 放一面单旗，右键，观察粒子边界。
2. 再放第二面旗形成闭合面，右键任一面旗。
3. 期望：粒子覆盖整个连通保护区域，不只是“米字”射线。
4. 记录：实际受保护区块数与粒子外框是否一致。

## 8. 停服日志复看（T-05）

**目的**：停服瘦身失败不再只打印 `null`。

1. 正常 `/stop` 停服一次。
2. 查 `logs/latest.log` 中 `debug rewind compact` / 区域压缩相关行。
3. 期望：失败时是 `异常类型: 消息`，不是 `: null`；成功时无异常刷屏。
