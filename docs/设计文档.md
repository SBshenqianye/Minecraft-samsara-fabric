## 1. 背景与目标

### 1.1 旧项目回顾

旧项目是一个 Spigot 插件，核心目标：**游戏大版本更新后自动删除白名单外的旧区块**，让新结构就近生成，玩家不用跑远图，同时保留玩家建筑。白名单机制是"旗帜圈地"：玩家放置带图案+染料的旗帜，图案映射 8 个方向、染料颜色序号映射延展距离，服务端把旗帜解析为节点，再通过线段组合并（"化线为面"）计算保护区域。

现状：**半成品，未跑通**。几何部分（Extension/Node/ChunkCoordinate）完成；`Area` 线段合并有 bug 且每次事件新建实例（字段全为 null，必然 NPE）；"化线为面"核心算法直接 `return null`；数据持久化只建文件从不读写；备份/删除功能完全没写。

### 1.2 新目标

在保留旧项目初衷（版本更新不丢建筑）的基础上，把范围扩大到**周目生命周期管理**：

1. **周目管理**：服务器按"周目"（Season）运营，可创建、开始、结束、归档周目，记录每个周目的时间与出生中心；
2. **新周目传送**：开新周目时，全员传送到距离旧出生点较远的全新位置；
3. **分组分散出生**：玩家三五成群（每组 3~5 人）围绕出生点分散在不同位置，避免开局挤在一起抢资源；
4. **活跃度分析**：分析存档"多久没有玩家来玩"，辅助判断当前周目状态；
5. **区块管理**：保留旧项目的**旗帜多边形圈地**（继续填"化线为面"的坑），版本更新时备份 + 按白名单删除旧区块。

### 1.3 框架决策

**结论：Fabric 服务端（目标 26.2）+ 小服务端模组 + 数据包 + 离线分析脚本。**

| 框架 | 结论 | 理由 |
|---|---|---|
| Fabric | ✅ 采用 | 服务端=原版+模组，红石行为与原版一致；Carpet/Lithium/Chunky 生态；版本跟进最快 |
| Spigot/Paper | ❌ 不采用 | 红石时序/更新顺序存在已知原版偏差 |
| NeoForge | ❌ 不采用 | 内容模组平台，管理类工具生态弱、升级慢 |

## 3. 周目（Season）模型

### 3.1 核心概念

**周目 = 一个游玩纪元**，包含：编号、名称、开始/结束时间、出生中心、分组出生点、世界模式、备注。

### 3.2 世界模式（双模式，创建周目时任选）

| 模式 | 说明 | 适用 |
|---|---|---|
| **same-world** | 单世界滚动：新周目把出生中心搬到远处（距旧中心 15000~40000 格随机方向），旧建筑原地保留；周目更替走**时间倒流**（§10）退场 | 想保留旧世界且体验"逆熵"仪式感 |
| **new-world** | 新建独立世界（world_sN，**可输入种子**），旧世界完整保留并**冻结归档（不进行时空逆转）**；全员强制迁移至新世界，旧世界通过**世界栈**往返（§12） | 想要彻底新地图/新种子开局 |

> 两种模式在 `/samsara season create` 时任选；new-world 模式下旧世界形成**世界栈**（§12），**倒流仅用于 same-world**。

### 3.3 数据模型（`config/samsara/season.json`）

```json
{
  "schemaVersion": 1,
  "currentSeasonId": 3,
  "worldStack": ["world_s1", "world_s2", "world"],
  "seasons": [
    {
      "id": 1,
      "name": "S1 初探",
      "mode": "new-world",
      "worldName": "world_s1",
      "seed": 123456789,
      "startTime": 1750000000,
      "endTime": null,
      "spawnCenter": { "x": 0, "z": 0 },
      "spawnRadius": 1500,
      "groupSpawns": [
        { "x": 120, "z": -80, "playerUuids": ["uuid-a", "uuid-b"] }
      ],
      "note": ""
    }
  ],
  "settings": {
    "groupSizeMin": 3,
    "groupSizeMax": 5,
    "groupMinDistance": 1000,
    "spawnRadius": 1500,
    "spreadMinRadius": 500,
    "spreadMaxRadius": 2000,
    "newCenterMinDistance": 15000,
    "newCenterMaxDistance": 40000,
    "rewindDurationDays": 1.0,
    "birthpointJitter": 40,
    "resetIndividualBirthpoint": true
  }
}
```

### 3.4 周目状态机

```
PENDING ──(create)──> ACTIVE ──(end)──> ENDED ──(archive)──> ARCHIVED
                          │
                          └──(全员同意/管理员执行)──> 触发开新周目
```

- `PENDING`：已创建未开始（只写配置，不动世界）
- `ACTIVE`：进行中（记录统计）
- `ENDED`：已结束（保留数据，等待归档）
- `ARCHIVED`：已归档（new-world 模式旧世界**冻结入世界栈** §12，仍可往返访问；same-world 模式仅留记录）

## 4. 新周目启动流程

`/samsara season start`（管理员）或 全员同意后执行 时序：

1. **校验**：当前周目为 ACTIVE → 二次确认；无可倒流区块时回退为直接传送；
2. **计算新出生中心 / 建新世界**：same-world = 新中心与全部历史中心集合距离都 ≥ newCenterMinDistance；new-world = 以输入种子新建世界并压入世界栈（§12）；
3. **预热出生区（可选）**：调用 Chunky 或模组内预生成出生中心周围 spawnRadius 区块；
4. **分组分配**：
   - 输入：注册玩家列表（`usercache.json` + `playerdata/`），按最后上线时间排序；
   - 组大小 3~5 人，组数 = ceil(人数 / 5)；
   - 每组生成一个出生点：围绕出生中心，极角按组序号均分 + 随机抖动，半径在 spreadMinRadius~spreadMaxRadius 之间，且组间距离 ≥ groupMinDistance；
   - 出生点写入 `season.json` 的 `groupSpawns`；
   - **每人独立系统出生点**：若 `resetIndividualBirthpoint=true`，把每个玩家重置到各自组出生点 + 由 UUID 确定的抖动；
5. **全员传送**：逐组执行传送；**保留背包/末影箱/进度**（玩家数据与 UUID 绑定，天然跨世界保留）；
6. **广播**：新周目编号、出生区坐标、玩法说明；
7. **收尾**：旧周目 `endTime` 落库、状态置 ENDED；新周目置 ACTIVE、`startTime` 落库。

> 分组出生也可临时执行（不开新周目）：`/samsara season respawn-groups` 重新分配当前玩家分组。

## 5. 活跃度分析

### 5.1 数据来源

| 文件 | 字段 | 含义 |
|---|---|---|
| `config/samsara/activity.log` | 时间戳 | **玩家上下线事件日志（主数据源）** |
| `world/usercache.json` | `expiresOn` | 缓存过期时间 ≈ 最后登录 + 3 个月 |
| `world/stats/<uuid>.json` | 各统计项 | 游玩时长、死亡数等（辅助） |

### 5.2 指标定义

**周目维度：**
- 最近 7 / 14 / 30 天活跃玩家数
- 日均在线（模组统计在线时长 / 天数）
- 峰值在线（日志取 max）

**玩家维度分类：**
- 活跃：7 天内登录过
- 回归：8~30 天前登录过且总时长 ≥ 10 分钟
- 流失：31~60 天未登录
- 沉睡：> 60 天未登录

### 5.3 呈现形式

1. **`/samsara season status`**（服务端内）：当前周目 + 活跃度段落；
2. **`/samsara activity [recent|stats|dead]`**：完整活跃度查询；
3. **离线脚本 `tools/analyze.py`**（零依赖，Python 3 标准库）：读 activity.log 输出报告。

## 6. 区块管理

### 6.1 触发场景

- **场景 A（版本更新）**：MC 大版本升级后，删除未保护区块，让新结构就近生成；
- **场景 B（新周目 new-world）**：旧世界整体归档/删除（走 §3 世界模式流程）。

### 6.2 白名单体系

**两级白名单：旗帜多边形圈地（主）+ 配置白名单（辅）。**

#### 6.2.1 旗帜多边形圈地（主）

沿用旧项目机制：玩家放置带图案+染料的旗帜 → 图案映射 8 方向延展、染料颜色序号映射延展距离（1~16 区块）→ 节点产生"影响坐标集" → 线段集合经"化线为面"（§6.3）计算白名单区块坐标集。

##### 图案→方向映射（MC 26.2 asset_id）

| MC 26.2 asset_id | 方向 | 视觉 | 扩展方式 |
|---|---|---|---|
| `"stripe_top"` | Up（北，Z-） | 顶部横条 | 单向 |
| `"stripe_bottom"` | Down（南，Z+） | 底部横条 | 单向 |
| `"stripe_left"` | Left（西，X-） | 左侧竖条 | 单向 |
| `"stripe_right"` | Right（东，X+） | 右侧竖条 | 单向 |
| `"square_top_left"` | LeftUp（西北） | 左上方块 | 单向 |
| `"square_bottom_left"` | LeftDown（西南） | 左下方块 | 单向 |
| `"square_top_right"` | RightUp（东北） | 右上方块 | 单向 |
| `"square_bottom_right"` | RightDown（东南） | 右下方块 | 单向 |

**组合图案**（一个图案同时激活多个方向）：

| MC 26.2 asset_id | 激活方向 | 视觉 |
|---|---|---|
| `"stripe_center"` | Up + Down | 中心竖条 |
| `"stripe_middle"` | Left + Right | 中心横条 |
| `"stripe_downleft"` | LeftDown + RightUp | 反斜线 |
| `"stripe_downright"` | LeftUp + RightDown | 正斜线 |
| `"cross"` | 4 个对角 | X 形 |
| `"straight_cross"` | Up+Down+Left+Right | 十字 |
| `"border"` | 全部 8 方向 | 边框 |

同一方向可被多个图案叠加，每个方向取最大值。

##### 染料→距离映射

MC 染料 `Color` 字段（int 0-15）+ 1 = 扩展距离（区块数）：

| 颜色 | Color 值 | 距离 | 颜色 | Color 值 | 距离 |
|---|---|---|---|---|---|
| 白 | 0 | 1 | 浅灰 | 8 | 9 |
| 橙 | 1 | 2 | 青 | 9 | 10 |
| 品红 | 2 | 3 | 紫 | 10 | 11 |
| 浅蓝 | 3 | 4 | 蓝 | 11 | 12 |
| 黄 | 4 | 5 | 棕 | 12 | 13 |
| 黄绿 | 5 | 6 | 绿 | 13 | 14 |
| 粉 | 6 | 7 | 红 | 14 | 15 |
| 灰 | 7 | 8 | 黑 | 15 | 16 |

##### 旗帜朝向（FACING）旋转校正

旗帜的 `Rotatable` 属性对整个方向集做旋转。北朝向=不旋转，其他朝向按 45° 递增顺时针旋转：

| FACING | 旋转次数 | 效果 |
|---|---|---|
| north | 0 | 不旋转 |
| north_east | 7×45°=315° | `ts`→东 |
| east | 6×45°=270° | `ts`→东 |
| south_east | 5×45°=225° | `ts`→东南 |
| south | 4×45°=180° | `ts`→南 |
| south_west | 3×45°=135° | `ts`→西南 |
| west | 2×45°=90° | `ts`→西 |
| north_west | 1×45°=45° | `ts`→西北 |

旋转方法：每次 45° 顺时针，8 个方向值循环移位：
`Up→RightUp→Right→RightDown→Down→LeftDown→Left→LeftUp→Up`

##### 放置检测与交互

- **放置时**：检测旗帜 NBT 的 `Patterns` 列表，若包含上述 15 种方向图案之一 → 识别为圈地旗，注册为节点；
- **右键已放置旗帜**：解析 NBT → 显示方向+距离+所属圈地区域信息；
- **旗帜被拆**：默认保留圈地（防误拆丢范围），提供 `/samsara debug claim rebuild` 手动重算。

### 6.3 "化线为面"算法设计（核心）

#### 6.3.1 问题定义

输入：节点集合（旗帜所在区块坐标）+ 线段集合（节点与其影响坐标的连线），端点均为整数区块坐标。

输出：白名单区块坐标集 = **封闭图形（边界 + 内部）∪ 开放折线（线上所有整数格点）∪ 孤立点（单节点）**。

#### 6.3.2 格点图方案

1. **线段光栅化**：对每条线段 (x1,z1)→(x2,z2)，步长 = (dx/g, dz/g)，g = gcd(|dx|, |dz|)；
2. **建图**：格点集 + 格点边集构成无向图；
3. **求封闭图形（环/面）**：半边缘遍历（half-edge / face traversal）；
4. **边界点集**：组成每个有界面的全部格点；
5. **内部点集**：**扫描线填充**——对包围盒内每一行 z，求该行与所有边界边的交点，排序后成对填充；
6. **开放折线点集**：不在任何有界面上的线段格点；
7. **孤立点**：无任何边连接的节点；
8. **并集** → 白名单区块坐标集。

#### 6.3.3 正确性用例（单测清单）

- 单个节点（孤立点）→ 只有该区块
- 单条线段（两节点）→ 线上所有格点
- 正交正方形四角 → 边界 + 内部
- 斜边菱形 → 边界 + 内部
- 两条斜线十字交叉 → 正确连通
- 封闭图形 + 外伸折线 → 并集
- 相邻封闭图形共享边 → 各自内部均正确
- 凹多边形 → 内部填充正确
- 空输入 / 单线段退化 → 不崩溃

### 6.4 状态持久化与服务化

- `AreaService`：单例服务，从 `config/samsara/claims.json` 加载（节点集、白名单缓存），每次变更后异步节流落盘；
- `LineSegment` 补 equals/hashCode；
- 数据文件统一 JSON。

### 6.5 删除流程

```
1. 收集非白名单区块（白名单索引快路径）
2. 入队 PendingDeleteQueue（仍加载的区块）
3. drainNonLoaded 立即处理未加载区块（后台线程备份+清零）
4. 已加载区块 → 卸载即删（CHUNK_UNLOAD 钩子）
5. 启动/停服窗口兜底清空待删队列
6. 清零后全空 .mca 整文件删除；停服窗口 compact 压缩重写残留文件
```

### 6.6 安全约束

- 删除前必须 dry-run 预览；
- 双保险：.mca 级备份 + 整档 zip；
- 提示玩家：箱子/潜影盒内容在区块文件内，会被删除；背包/末影箱/进度安全；
- 白名单校验以区块坐标为单位。

## 8. 全员同意制（M8）

> 状态：设计稿（2026-08-30）

### 8.1 设计理念

**自然地通过游戏操作来开启新周目**，而非纯指令驱动。适合小团体服务器——玩家自己商量是否开新周目，不需要管理员在场。

### 8.2 核心机制

- **管理员**（OP level 2+）可随时直接执行 `/samsara season start`
- **无管理员时**，任何玩家输入 `/samsara season advance` 发起
- 发起后需要**在线玩家全员同意**（`/samsara season agree`）
- **在线 >1 人才允许发起**（防止单人自开）
- **48 小时内未达成全员同意** → 发起自动过期

### 8.3 命令

| 命令 | 权限 | 说明 |
|---|---|---|
| `/samsara season advance` | 所有人（需在线>1人） | 发起开新周目 |
| `/samsara season agree` | 所有人 | 同意开新周目 |
| `/samsara season vote-status` | 所有人 | 查看当前同意状态 |

### 8.4 流程

```
玩家A 输入 /samsara season advance
    ↓
系统广播："玩家A 发起了开新周目，输入 /samsara season agree 同意"
    ↓
其他玩家逐个输入 /samsara season agree
    ↓
在线全员同意 → 等同于 /samsara season start 执行
    ↓
48h 未达成 → 过期，广播通知
```

### 8.5 与现有功能的关系

## 10. 时间倒流（逆熵引擎）

> 状态：**已实现**（档1~档3 + 倒流完成即自动物理删除）。

### 10.1 概念

- **瞬间重启**：删未圈地区块文件，加载时重生成；
- **缓慢重启（时间倒流）**：以一天为周期，未圈地区块"均匀地"回到新生成时的模样。

### 10.2 三档实现

| 档位 | 机制 | 存储 | 效果 |
|---|---|---|---|
| 档1 瞬间重启 | 删未圈地区块文件 | 0 | 一步到位 |
| 档2 区块级波浪 | 每个未圈地块分配倒流时刻，到点删除 | 0 | 区块粒度退场 |
| 档3 方块级平滑 | 记录每个被修改方块的原状态，按进度恢复 | 差异库 | 电影级回填 |

### 10.3 差异库

**记录范围：**
- ✅ 记：玩家破坏/放置、爆炸导致的方块变化
- ❌ 不记：红石刻状态变化、作物生长、流体流动等世界模拟噪声

**存储估算：** 单条 ≈ 12~20B；10 活跃玩家 ≈ 0.2~6MB/天。存储不是瓶颈。

### 10.4 倒流节奏：按区块更改进度均匀恢复

每个区块的恢复速率与修改量成正比，保证所有区块在一天结束时完成倒流。

### 10.5 倒流期间的行为规则

- **快照语义**：倒流只回滚"倒流开始时已存在的修改"，倒流期间的新改动不受影响；
- **懒加载**：只对玩家当前加载的区块做实际方块恢复，未加载区块在被加载时"跟上时刻"；
- **圈地暂停**：倒流期间玩家圈地的区块立即暂停倒流；
- **对未记录区域**：用"删除/重生成"兜底。

### 10.6 记录层（diff 系统，兼作 M6 记录层基础）

`DiffRecorder` 同时承担两个职责：
1. **倒流差异记录**：记录方块变化，供档3 恢复使用；
2. **玩家轨迹记录**（基础能力）：可扩展为记录玩家位置/朝向/动作，供未来重放使用。

数据格式：每条 24 字节（stateId + x + y + z + timeMs），存储在 `config/samsara/diff/`。

### 10.7 物理删除

倒流完成即自动执行：备份 + 卸载 + 清零区块槽 → 重启后按当前版本重新生成。全空 .mca 整文件删除；停服窗口 compact 压缩重写残留文件。

## 11. 世界栈（双世界模式与跨世界传送）

> 状态：预留（M7）。

### 11.1 概念

- **same-world**：单世界滚动，周目更替走时间倒流（§10）；
- **new-world**：新建独立世界，旧世界完整保留并冻结归档，全员强制迁移至新世界，旧世界通过**世界栈**往返访问。

### 11.2 世界栈模型

- 世界按周目叠放成栈：最新世界 = 栈顶，旧世界依序压栈；
- 每层独立文件夹、独立种子、独立下界/末地；
- `season.json` 维护 `worldStack`（栈底→栈顶）与当前世界指针。

### 11.3 跨世界往返

- **下（新世界 → 旧世界）**：下界基岩天花板往下打穿 → 传送到旧世界对应坐标；
- **上（旧世界 → 新世界）**：主世界搭方块到 Y>320 → 传送到新世界对应坐标。

### 11.4 强制迁移

新周目开始时全员传送至新世界出生区；背包/末影箱/进度天然保留。
