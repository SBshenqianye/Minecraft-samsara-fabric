# ADR-012: 宠物多主人（v0.20）

- 日期：2026-10-30
- 状态：已实施（v0.20.0，2026-10-30）
- 关联：《设计文档》〈宠物多主人〉、F-49~F-52

## 背景

原版宠物只存一个 `Owner` UUID。直接把它改成数组会让原版读取失败（类型不匹配）。用户希望宠物可以多次认主，成为“大家的宠物”。

## 决策

1. **保留原版 `Owner` 标量**，不改变类型。
2. **额外主人写入自定义 NBT 列表** `samsara:owners`，原版忽略，不报错。
3. **主主人用于原版 AI**：跟随/传送/死亡消息优先主主人。
4. **所有主人拥有主主人权限**：坐下/站起、染色、喂食、繁殖、交互。
5. **跟随优先级**：主主人 → 手持驯服物品的最后持有者 → 最近在线主人 → 原地等待。
6. **重复认主**：任何玩家用对应驯服物品右键已驯服宠物即可加入 owner；同一身份组按 data UUID 去重；上限 32。
7. **纯原版保存可能丢失 `samsara:owners`**：主主人保留，接受降级。

## 为什么不是其它方案

- **把 `Owner` 改成数组**：原版读取会类型不匹配，存档不兼容。
- **只做外部 sidecar 映射**：实体复制/跨世界时容易丢映射；NBT 随实体走更自然。
- **只允许主主人**：无法实现“大家的宠物”。

## 后果

- 需要 `TamableAnimalMixin` 拦截读写与 `isOwnedBy`；Wolf 等特殊交互可能还需补充 mixin。
- 额外主人列表有过期/上限问题，需要 Web/命令或交互清理（首版只加不删）。
- 纯原版保存会丢额外主人，属于已知边界。
