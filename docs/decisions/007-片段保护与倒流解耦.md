# ADR-007: 片段收藏保护优先，且与倒流/diff 解耦

> 日期：2026-10-30
> 状态：已采纳
> 关联：《需求文档》F-103 / F-104；《设计文档》〈片段收藏与保留保护〉；《设计规范》〈回看 2.0：片段、事件、聊天〉

## 背景

回看轨迹会随年龄做几何降采样：1/4/16/64/256 天档位，RDP 误差 0.5 格/档。收藏的 PvP/团队片段如果也被稀释，远期只剩骨架点，回看时看不清动作。

用户提出的备选是“允许稀释，但倒流/回溯时着重播放”。需要裁决哪种更好，并确认不会破坏倒流与方块 diff。

## 决策

1. **收藏区间在保留扫描中保持原采样密度**，即“保护不被稀释”。
2. **保护只作用于 `track/*.bin` 的样本保留**，不读写 `diff/`，不改变 `season.json`、倒流时长、双光标 A/B、区块删除。
3. **降采样只删除样本，不修改 `timeMs`、不重排样本**；保护只会让插值更密，不会让轨迹与方块时间轴错位。
4. 收藏仍遵守捕捉截断（F-93）；收藏段被 cutoff 截断时只播到 cutoff。
5. 回看列表/控制条同时提供收藏段高亮与一键跳转；“着重播放”是体验层，不是存储层的替代。

## 理由

- 当前的“倒流”只恢复方块（`RewindEngine`/`DiffRestore`），**没有播放玩家轨迹的环节**；“倒流时着重播放”没有承载点，要做等于新开一个子系统。
- 强调不能恢复已经被删掉的采样；如果先稀释，远期收藏段仍然模糊。
- 收藏片段通常很短（秒级到分钟级），保护成本可控；按天轮转的文件只需在命中区间跳过 RDP。
- 与 diff 解耦是硬边界：`TrackRecorder.sweep` 只遍历 `track/`，不触碰 `diff/`；保护实现不得跨层调用。

## 后果

- 收藏会让部分历史文件保持较高密度，存储上限需要单独观察；超出上限时优先限制收藏段数量/长度，而不是取消保护。
- 验收必须做“收藏前后 `.bin` 首末时间戳不变、`diff/` 与 `season.json` SHA256 不变”的对比。
- 若未来真的加入“倒流期间播放轨迹”，收藏保护会改善对齐，而不是恶化；届时再评估是否需要在倒流侧强调收藏段。
