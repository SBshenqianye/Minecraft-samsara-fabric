# ADR-008: 不引入客户端模组；滚轮/真拖动不做

> 日期：2026-10-30
> 状态：已采纳
> 关联：《需求文档》F-102；《设计文档》〈时间轴跳转与输入限制〉

## 背景

回看进度条希望支持“按住修饰键 + 滚轮”或拖动。服务端排查结论：

- vanilla 客户端在旁观模式下把滚轮交给 `SpectatorGui`（旁观菜单），**不发送普通滚轮包**；
- 服务端模组只能接管已经存在的包，不能凭空获得客户端输入；
- 要拿到滚轮/拖动，必须让客户端装一个输入组件，或把游戏模式改成非旁观再模拟旁观行为。

## 决策

**不引入任何客户端模组。**

- 不做可选客户端组件，不做 HUD 圈，不做真拖动条。
- 回看进度调节只使用服务端可用的方式：聊天栏点击按钮（±10s/±30s、25%/50%/75%）、`/samsara track view seek` 命令、回看开始时间窗口。
- 保持“核心功能客户端免装模组”的产品承诺。
- 若未来仍需要“按住键快速调节”，只考虑服务端已收到的移动输入（例如 W/S 拖动模式），不改变客户端安装前提；该功能当前不实现、不纳入承诺。

## 理由

- 用户明确拒绝客户端安装额外模组。
- 改游戏模式模拟旁观会丢失无碰撞/穿墙/自由飞行等关键体验，且交互路径容易漏，回归风险高。
- 点击按钮 + 命令已经覆盖跳转、微调、百分比定位与片段跳转的全部功能面，只是输入方式不如滚轮顺手。
- 服务端模组无法拦截不存在的包，这是协议边界，不是实现取舍。

## 后果

- F-102 的验收口径改为“服务端点击/百分比/命令可用；滚轮与真拖动不做”。
- 回看控制条需要保持可点击按钮的完整覆盖；任何新增跳转能力都必须有命令入口，便于 RCON 与无客户端场景使用。
- 若以后改变“客户端免装”策略，需要新的 ADR，不在此决策上直接扩展。
