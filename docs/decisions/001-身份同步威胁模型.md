# ADR-001: 身份同步安全威胁模型

> 日期：2026-09-07
> 状态：已采纳
> 关联：《设计文档》〈安全威胁模型〉

## 背景

samsara 的身份同步系统需要在离线模式（`online-mode=false`）下管理玩家身份。离线模式的固有缺陷带来了多个安全威胁。

## 威胁分析

### 1. 离线模式身份冒用（高风险）

离线模式下无任何认证，任何玩家可输入任意用户名登录。离线 UUID 算法是确定性的——同名永远得到同 UUID。

**攻击场景**：
1. 玩家"RealSteve"用"Steve"登录，建立圈地、积累背包
2. 攻击者"FakeSteve"也用"Steve"登录离线服务器
3. FakeSteve 获得与 RealSteve 完全相同的离线 UUID → 继承圈地归属权

**缓解**：密码保护（《设计文档》〈密码保护与命令〉）+ 白名单 + 身份组锁定。

### 2. 正版改名身份断裂（低风险）

正版 UUID 是 Mojang 分配的 type-4 随机 UUID，改名后 UUID 不变，核心身份不会丢失。但 identity.json 中的 name 是快照，不会随 Mojang 改名自动更新。

### 3. 服务器模式切换（中风险）

| 切换方向 | 现象 |
|---|---|
| offline → online | 原离线玩家获得新 type-4 UUID，成为"新人" |
| online → offline | 原正版玩家的 type-4 UUID 保留，但用名字重新登录会额外获得 type-3 UUID |

### 4. 离线模式无法识别正版玩家（设计盲点）

当服务器以 `online-mode=false` 启动时，不会联系 Mojang 认证服务器，无法验证任何玩家的正版身份。所有玩家都是 type-3 离线 UUID。

**结论**：身份组的建立只能依赖管理员手动操作或密码保护下的自动注册。

### 5. 同步导致物品复制（需防御）

如果身份组内的 UUID 之间同步不一致，可能导致物品复制。通过星型全状态同步 + 身份组锁定彻底消除此风险。

## 决策

采用**密码保护 + 星型全状态同步 + 身份组锁定**的组合方案，在离线模式下提供足够的安全保障。
