# ADR-003: 星型全状态同步拓扑

> 日期：2026-09-07
> 状态：已采纳
> 关联：《设计文档》〈身份同步的核心原则〉

## 背景

身份组内多个 UUID 需要共享玩家数据。需要确定同步拓扑和同步范围，同时防止物品复制。

## 替代方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 完全不同步 | 无复制风险 | UUID 切换后数据丢失 |
| 网状同步（所有 UUID 互相同步） | 灵活 | 复制风险高，并发难控制 |
| **星型同步（canonical 为枢纽）** | 简单、可控、无复制 | canonical 是单点 |
| 实时同步 | 体验最好 | 复制+远程仓库，无法防御 |

## 决策

采用**星型全状态同步**：
- canonical UUID 为枢纽，所有离线 UUID 通过 canonical 同步
- 离线 UUID 之间不同步
- 同步范围：inventory + position + effects + advancements + stats 等全状态
- 同步时机：登录 + 退出双向同步

## 安全性证明

```
1. premium A (canonical) 有64钻石 → 退出 → canonical A: 64
2. offline B 登录 → canonical→B → B:64
3. B放入箱子 → B:0, 箱子:64 → 退出 → canonical A: 0
4. offline C 登录 → canonical→C → C:0
5. C从箱子取64 → C:64 → 退出 → canonical A: 64
6. premium A 登录 → canonical A: 64
→ 无物品复制 ✅
```
