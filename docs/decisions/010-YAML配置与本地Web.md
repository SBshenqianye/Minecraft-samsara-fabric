# 010 · YAML 配置与本地 Web 管理

- 日期：2026-10-30
- 状态：已实施（v0.18.0，2026-10-30）
- 相关：`docs/需求文档.md` F-121~F-126、`docs/设计文档.md`〈配置格式与本地 Web 管理〉、`docs/设计规范.md`〈配置与数据分层约定〉〈本地 Web 约定〉

## 背景

当前配置是 JSON：没有注释、不能表达“这个键是干什么的”，而且只写用户改过的键，导致“文件里没有但代码里可配”的键很难被发现。服主只能翻文档或源码。

Web 面板原本排在远期，但“管理配置”是本地、低风险、可独立交付的能力，适合提前做；它也能反过来推动配置 schema 化。

## 决策

1. **配置统一 YAML**：`commands.yml`、`permissions.yml`、`claim-particles.yml`、`storage.yml`、`web.yml`。`storage.yml` 的 `globalFollowWorld` 控制全局数据随存档还是服务器级。
2. **Schema 驱动**：每个键在 `ConfigSchema` 注册类型、默认值、范围、说明、分组、是否重启；加载、生成、Web 表单、校验共用。
3. **首次生成完整配置**：所有键（含默认值）和注释一次性写出；缺键读取默认值；非法值回退并警告。
4. **本地 Web 只做配置**：JDK 自带 `HttpServer`，默认 `127.0.0.1:8720`，Bearer token；支持查看/编辑/校验/保存/重载/状态；不通过 Web 改世界数据或执行命令。
5. **JSON 只保留给机器格式**：旧 JSON 配置迁移为 `.yml`，旧文件改名 `.json.legacy`；活动/审计/聊天继续 JSONL，轨迹/差异继续二进制。

## 为什么不是其它方案

- **继续 JSON + 手写文档**：无法解决“默认键不可见”，也不适合做表单。
- **TOML/INI**：嵌套结构（权限路径、粒子分时段）表达不如 YAML 自然；YAML 与现有文档/配置习惯更接近。
- **引入 Spring/前端框架**：本地单页配置管理不需要；JDK HttpServer + 原生 JS 足够，依赖越少越稳。
- **Web 绑定 0.0.0.0**：会把服主配置暴露到局域网/公网；首版明确只监听回环。
- **Web 直接改世界数据**：风险高，首版只读展示路径/统计；等权限与审计模型稳定后再评估。

## 后果

- 需要引入 SnakeYAML（JiJ），并保证 jar 体积与类加载不冲突。
- 需要一次性迁移旧 JSON；迁移失败必须保留旧文件。
- 配置 schema 成为新的“事实来源”，新增配置项不能只加字段不注册 schema。
- 本地 Web 需要 token、限长、固定路径、字段级校验等基本安全措施。
- 测试需覆盖 YAML 往返、schema 校验、旧 JSON 迁移、HTTP 鉴权失败、非法值拒绝、保存成功、端口占用降级。
