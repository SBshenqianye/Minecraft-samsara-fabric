# ADR-011: 身份组与独立 data UUID（v0.20）

- 日期：2026-10-30
- 状态：已实施（v0.20.0，2026-10-30）
- 关联：《设计文档》〈身份组（身份映射，v0.20 重新设计）〉、F-39~F-48

## 背景

v0.19 把身份组做成了“认证系统”：注册、登录、密码、限流、封禁、身份组锁定。实际使用场景是私服：身份安全由其他认证模组负责，samsara 真正需要的是**把多个账号入口归到同一份数据归属**。

## 决策

1. **删除认证层**：不提供注册/登录/密码/限流/封禁/身份组锁定。
2. **身份组由 Web 手动维护**：`config/samsara/identity.yml`，字段 `name/premium/offline/data/note`。
3. **data UUID 独立**：每组一个数据 UUID，可以不是任何玩家账号；玩家数据、归属聚合以 data 为准。
4. **账号切换才同步**：`lastWriter` 记录最后写入账号；同账号重连不同步，premium ↔ offline 切换时同步。
5. **归属统一**：归属/事件数据写实际 UUID；查询/权限/统计解析到 data。
6. **不做组锁**：前提是正版服/盗版服互斥；若未来代理/混合模式允许同时登录，必须重新引入锁。
7. **data UUID 重绑受控**：Web 修改 data 必须预览、备份、确认；新 data 已有数据时默认拒绝。

## 为什么不是其它方案

- **继续做认证**：与用户目标不符，且引入密码/日志/限流/防冒用等大量非目标复杂度。
- **data UUID 固定为 premium/offline**：换号或删号会牵连数据主键；独立 UUID 更稳定。
- **每次登录都同步**：增加 I/O 与失败面；只在账号切换时同步足够。
- **写数据时直接写 data UUID**：旧数据需要批量迁移；读时聚合更安全。

## 后果

- 身份安全不再是 samsara 的职责，必须由其他模组/白名单补足。
- 删除 alias 后，其历史圈地/事件数据变成该实际 UUID 的“无主”数据。
- Web 必须提供身份组校验、预览与 data 重绑保护。
- 多栈世界下身份配置固定 `config/samsara/identity.yml`，身份运行时数据放 `<主存档根>/samsara/identity/`：随主存档复制/备份，但不随世界栈或 `globalFollowWorld` 切换。
- 只转移存档时身份运行时数据会一起走；`identity.yml` 是服务器级配置，需要同时复制或使用 Web 导出/导入。
