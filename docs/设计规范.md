## 1. 命名与显示

- 模组显示名：**周目管理**（samsara 为代号/标识符）。
- 命令反馈格式：使用 `ChatFormat` 统一格式化（`command/ChatFormat.java`）
  - 首行 `[周目管理] ▸ 消息内容`，便于与上一条消息视觉区分
  - 后续行 `  ▸ 消息内容` 缩进对齐
  - 调试命令使用 `[周目管理·调试] ▸` 前缀
  - 自动换行：CJK 字符按2宽度、ASCII 按1宽度，默认34宽度单位
  - 玩家级宽度配置：`ChatFormat.setPlayerWrapWidth(uuid, width)`
- 日志输出用 `[samsara]` 前缀。

## 2. 命令输出约定

- **时间**：一律用**系统本地时区**（`LocalDateTime.ofInstant(ms, ZoneId.systemDefault())`），格式 `yyyy-MM-dd HH:mm:ss`。
  ⚠️ 禁止用 `Instant.toString()`（那是 UTC，会把本地时间显示错 8 小时）。
- **路径**：一律 `toAbsolutePath().normalize().toString()`，去掉 `.\` 等冗余段。
- **多行/列表**：每条占一行；不同"块"之间用空行分隔；单条信息内用 ` · `（间隔号）连接字段。
- **分隔线**：列表分页时页码行用 `--- 第 x/y 页，共 n 条 ---`。
- **对齐**：反馈统一走 `src.sendSuccess(() -> ChatFormat.formatComponent(msg), false)`（常规命令）或 `ChatFormat.formatDebugComponent(msg)`（调试命令）。
- **重要信息放末尾**：会被长输出顶出可视区的关键信息（路径、总数等）放**输出最后一行**，避免被前面的长列表/长 JSON 刷出聊天区；长内容本身应引导走分页命令（如 `/season status [页码]`），而不塞进单条命令输出。
  - 示例：`/samsara debug status` 只回短概要（总数+当前+路径放末行），长列表交给 `/season status` 分页；`/samsara debug json` 末尾附 season.json 位置。

## 3. 列表分页

> 长列表（如 `/season status` 的周目列表）一律分页，`/season status` 无参即显示**第 1 页**（不再一次全出）。

**统一规则：**

| 维度 | 约定 |
|---|---|
| 命令形态 | 无参 = 第 1 页；`<页码>` 参数（命名统一 `page`，类型正整数） = 指定页 |
| 每页条数 | 默认 **8** 条（`pageSize = 8`，恒定，不在命令里暴露） |
| 页码越界 | 自动夹取到最后一页（`page = min(page, totalPages)`）；`totalPages = ceil(total / pageSize)` |
| 页脚 | 多页时追加 `--- 第 x/y 页，共 n 条 ---`；单页不显示页脚 |
| 空列表 | 显示"尚无 xxx，使用 …… 创建"（不分页） |
| 当前项 | "当前：xxx" 独立一行跟在列表后，不算分页条目 |

**实现分层：**

- **Manager 层**：`statusText(int page)` 承担分页切片、页脚、越界夹取 —— 纯逻辑，命令层不碰。
- **命令层**：只透传参数，`COMMANDS.literal("status")` 无参走 `statusText(1)`（第 1 页），带参走 `statusText(page)`。
- **最小值**：`pageSize` 为常量，未来若要可配再提取，首版固定 8。

**理由**：玩家/管理命令的反馈要一屏可读；分页比滚动更可控，且便于脚本化翻页（`/season status 1`、`/season status 2`…）。

## 4. 破坏性操作：二次确认

- **清空 / 删除等不可逆操作必须二次确认**：首次输入返回"确认？再次输入才执行"（内部置一个 armed 标记），再次输入才真正执行。
- 示例：`/samsara debug reset`（首次→提示；再次→执行）。

## 5. 时间戳一致性

- `startTime`/`endTime` 用 epoch 毫秒（`Instant.now().toEpochMilli()`）。
- 允许 debug 操作构造"时间倒挂"（start>end）以测试边界，但返回值**必须附带** `⚠ 该周目的开始时间晚于结束时间（时间倒挂）` 警告。

## 6. 单例化

- **Manager 一律单例**（`private static INSTANCE` + `public static synchronized getInstance()`，构造私有）—— 避免多入口各持一个实例导致状态不同步（曾出现 `/season` 与 `/samsara debug` 不同步 bug）。

## 7. 权限约定

| 命令 | 权限等级 |
|---|---|
| `/season status` `/season info` | 所有人 |
| `/samsara season status/info` | 所有人（查询） |
| `/season create/start/end` | `Permissions.COMMANDS_ADMIN`（OP level 2+） |
| `/samsara debug *` | `Permissions.COMMANDS_OWNER`（OP level 4 / 服主） |

- 用 26.x 的 `PermissionSet` 模型（`src.permissions().hasPermission(Permissions.XXX)`），不用旧 `hasPermissionLevel`。
- **命令命名空间（用户 2026-08-17 决策）**：**全部命令以 `/samsara` 开头**（避免与其他 mod 混杂）：`/samsara season` = 周目业务（`SeasonCommand.seasonNode()` 由 DebugCommand 挂到 `/samsara` 根）；`/samsara debug` = OWNER 调试。**新增命令必须先查/登记《设计文档》〈命令预留与命名空间规划〉的预留表**，未登记不得占用命名；实现后把 🔒 改 ✅。
- **短别名（2026-09-10 裁决：以 [`decisions/005-命令谦让策略.md`](decisions/005-命令谦让策略.md) 与《设计文档》〈命令规范〉为准）**：**所有命令均提供去掉 `/samsara ` 前缀的短别名**（如 `/samsara season status` → `/season status`），部分命令另有更短的惯用别名（`/register`、`/tpa`、`/tpyes`）。启动时逐个别名检测冲突：**已被其他模组注册则让位**，samsara 不抢占，仅保留 `/samsara` 全名；`/samsara <command>` 始终是保底路径。
  - 本条**推翻**本文件旧版"不留别名"的写法（旧写法与 [`decisions/005`](decisions/005-命令谦让策略.md)、《设计文档》〈命令规范〉、需求 `F-61` 冲突，故按决策记录日期较晚者收敛）。
  - 实现现状见《实现状态》〈整块未实现〉。

## 7b. 可点击指令与 Tab 补全（2026-10-29）

**唯一入口**：聊天栏按钮一律用 `command/ui/ChatUi`，Tab 补全一律用 `command/ui/SuggestionProviders`。禁止在命令类里直接 `new ClickEvent.RunCommand(...)` / `new ClickEvent.SuggestCommand(...)`（历史实现见 `ViewManager` 已迁移）。

### 7b.1 点击策略（硬约束）

| 场景 | 用哪个 | 例子 |
|---|---|---|
| 只读、幂等、无参数 | `ChatUi.run` | `version`、`mspt`、`tps`、`season status/info`、`claim info`、`where`、回看控制 |
| 破坏性、管理员、需要参数、容易误触 | `ChatUi.suggest` | `season start/end/skip/create`、`debug *`、`claim give/remove/delete`、`perm set/reset`、`tpa <玩家>` |

- 点击命令以玩家身份执行，**仍受** `requires(...)` 与 `PermissionChecker` 约束；不要为了“按钮能点”放宽权限。
- 需要按权限隐藏按钮时用 `runIf` / `suggestIf`（布尔）或 `runIfPermitted`（按 `/samsara <命令路径>` 的等级）；无权限时保留灰色同名文本，不保留 ClickEvent。
- 样式统一：`[标签]`、run=`AQUA`、suggest=`YELLOW`、禁用=`DARK_GRAY`、hover 为纯文本；命令自动补 `/`。
- 按钮只发给对应的人：TPA 的收件人消息只含 `[同意] [拒绝]`，发起者只含 `[取消请求]`；`tpa.enabled=false` 时不发按钮。
- 控制条只在会话开始/状态变化时发送，**不得**每 tick 刷屏。
- 长行不要依赖 `ChatFormat.wrap`（会在空格处拆开坐标/命令），自己按行拆。

### 7b.2 Tab 补全

- 所有玩家名参数必须补全：在线命令用 `playersProvider()`（TPA），可离线/历史玩家用 `knownPlayersProvider()`（回看、debug）。
- 周目/时长/回看选项/权限等级/命令路径/周目模式用现成 provider；小枚举用 `choices(...)`，坐标用 `chunkXProvider/chunkZProvider`（默认当前区块）。
- 补全项尽量带 tooltip（`Component.literal(...)` 作为 `Message`）。
- **前缀比较必须小写**：`getRemaining().toLowerCase(Locale.ROOT)`；不要在补全里做阻塞 IO——在线玩家/注入池走内存，`PlayerRegistry` 60s、周目目录 10s、回看时段 15s 缓存。
- **greedyString**（回看开始时间+选项、fakeplayers、groups、perm set）必须按“当前 token”补全：用 `SuggestionProviders.token(...)` 定位 token，再 `offerToken(...)` 手工构造 `Suggestions`，替换范围只覆盖当前 token。直接用 `builder.suggest(...)` 会按整段 remaining 过滤并整段替换，按 Tab 会吃掉已输入的开始时间。
- `greedyString` 必须位于参数树末尾；旧写法 `greedyString + word` 的后续参数永远解析不到（`perm set` 的等级曾因此失效）。

### 7b.4 未完成指令的聊天栏候选

- **只在服务端做**：客户端无需安装模组。入口是 `Commands.performCommand(...)` 头部的 mixin；只处理「解析不完整 / 没有可执行节点」，命令执行期异常保持原版。
- **只接管自己的根节点**：`CommandAliases.isSamsaraRoot(name)` 必须为 true；短别名注册成功时自动登记，`/samsara`、`/mspt`、`/tps` 等直接注册的根节点用 `CommandAliases.markRoot(...)` 登记。不要接管其他模组的报错。
- **候选与 Tab 同源**：必须走 `CommandDispatcher.getCompletionSuggestions(parse)`，不要在聊天栏另写一套候选表。前缀完全匹配不到时才用 `CompletionSupport.fuzzy(...)` 做近似匹配。
- **点击只填入**：一律用 `ChatUi.suggest` / `ClickEvent.SuggestCommand`，不得用 `RunCommand`；补全按钮需要尾随空格时由 `ChatUi` 保留，命令类不要手写 `ClickEvent`。
- **排版**：用 `CompletionGrid`。每个候选是一个完整按钮，不得把按钮拆到两行；一行放多个短候选，超长标签截断显示、点击仍填入完整命令。服务端宽度是估算值，不要用它做精确像素布局。
- **配置**：`commands.json` 的 `completion.chatList`（总开关）、`completion.fuzzy`（近似匹配）、`completion.maxItems`（展示上限）；不得把开关写死在代码里。
- **测试入口**：`/samsara debug completion <片段>` 打印候选与解析状态；`send` 形式用玩家身份实际发送。RCON 看不到点击事件，按钮点击仍需客户端人工确认。
- **v0.18 补全 2.0**：点击候选必须补一个分隔符（普通参数空格、逗号列表逗号），由 `ChatUi`/`CompletionGrid` 统一追加；有执行器的节点用 `[展开子命令]`，不得依赖尾随空格（客户端会 trim）；翻页用 `ClickEvent.Custom` + 服务端监听，不注册隐藏命令。详见《设计文档》〈补全交互 2.0〉。

### 7b.3 测试要求

- 点击组件：单测断言 `ClickEvent` 类型、命令文本（含前导 `/`）、hover 文本、颜色、无权限时无 ClickEvent。
- Tab 补全：单测断言纯数据列表、前缀过滤、greedy token 的 offset/token/候选，以及 `Suggestions.getRange()` 只覆盖当前 token。
- 聊天栏候选：单测断言多列排布不会拆开按钮、每个单元格都是 `SuggestCommand`、尾随空格保留、拼写近似只在无前缀匹配时触发、候选数量上限生效。
- RCON 看不到点击事件与 Tab 列表，服务端实测只能验证命令执行/文本；按钮实际点击需客户端人工确认。

## 8. 26.x API 要点（不要回退到旧命名）

- 类名用 Mojang 官方名：`CommandSourceStack`/`Commands`/`CommandBuildContext`/`Component`。
- 反馈方法：`sendSuccess(Supplier<Component>, boolean)`（不是 sendFeedback）。
- 参数类型：用 brigadier 原版（`com.mojang.brigadier.arguments.*`），26.x 已移除 MC 的 `*ArgumentType` 包装类。
- 世界信息：`src.getServer().getLevel(Level.OVERWORLD)` → `getSeed()`、`getRespawnData().pos()`（26.2 出生点机制，无 getSharedSpawnPos）。

## 9. debug 工具的用途约定

- `fakeplayers`：为**分组出生算法**生成离线玩家名单（名 → 离线 UUID，规则 `UUID.nameUUIDFromBytes("OfflinePlayer:"+名)`，与《设计文档》〈身份同步〉的 UUID 体系一致）。会**注入** `PlayerRegistry` 注入池（分组/预览时把这些玩家视为"刚上线"）。参数形态：
  - `clear` → 清空注入池；
  - 纯数字 `3` → TestPlayer1..3；
  - 前缀+数量 `guard 3` → guard1,guard2,guard3（前缀自定义，覆盖"按 ID 生成"场景）；
  - 名字序列 `Alice,Bob` → 逐个生成。
- `groups [名单]`：分组 **dry-run**（不落盘、不传送），缺省用注册玩家（注入池+在线+usercache+playerdata），指定名单用临时构造。
- `rewind preview|status|abort|purge|set <时长>`：时间倒流控制——预览扫描、状态、中止、立即删未保留区块、时长配置。
- **`claim` 子命令（现行实现，全部为区块坐标）**：`give <dir> <dist>`（给予指定方向+距离的圈地旗帜）、`list`（列出全部节点）、`rebuild`（全量重算白名单）、`scan`（扫描世界中已放置的圈地旗并补注册）、`remove <x> <z>`、`info <x> <z>`、`owner <x> <z>`（归属权）、`particle …`（昼夜/字体/光束粒子配置）、`delete dryrun|backup|execute|report`（安全删除生命周期）。
  - ⚠ 旧版的矩形圈地命令 `add <名> <p1> <p2>` / `addc <名> <p1> <p2>` / `remove <名>` 以及 `whitelist.json` 配置白名单**已废弃**（v0.8 起保护集仅旗帜圈地），现行代码中不存在——本文件旧版对它们的描述已按实现更正。

## 9b. 坐标参数语法糖（用户约定 2026-08-16）

凡涉及坐标的命令参数，一律使用**原版坐标参数类型**，**支持 `~`（相对当前执行者位置）与 `~N`（相对偏移 N 格）**，与 MC 原版指令语法一致；纯数字则为绝对坐标。RCON 下 `~` 相对世界出生点。

- 现行用法：`/samsara debug diff fake <pos>`、`/samsara debug rewind restore <pos>` 用 `ColumnPosArgument`（柱坐标 x z，命令内 ÷16 转区块）；`/samsara debug claim info|remove|owner <x> <z>` 用 `IntegerArgumentType`（**区块**坐标，不接受 `~`）。
- 旧版该节曾约定用 `Vec2Argument`/`Vec3Argument` 并举例 `claim add/addc`，但该组命令与 `Vec2Argument` 在现行代码中均不存在；类型名以本条现行用法为准。
- `create` 批量、`settime`、`reload`：围绕 season.json 的注入/操纵测试。
- 目标是：**不依赖真实玩家/不做长流程**就能验证后续功能（分组/传送等），把"便捷可测"作为 debug 集的第一原则。

## 10. 数据安全与协作约定（用户强约束，务必遵守）

- **绝不删除玩家世界 `world/`**。任何清理只碰**模组自身数据**（`season.json` 等），`world/`、`level.dat`、`playerdata/` 一律不动。
- **启动前自动备份**：`start-server.bat` 每次启动前把 `world` 复制到 `backups/world_<时间戳>/`（安全网）。
- **动手前确认**：需要删除/移动/覆盖任何用户侧文件前，先说明并等确认；不可逆操作按〈破坏性操作：二次确认〉执行。
- 背景教训：曾因"清理测试数据"误删 `world/` 造成损失（用户有备份才无碍），此规则为硬约束。

## 11. diff 记录窗口与恢复源（快照语义，用户 2026-08-17 修订）

> **路径口径（2026-10-30）**：本节的 `config/samsara/diff/...` 为旧路径；v0.18 起世界数据在 `<存档根>/samsara/diff/...`，且数据根已绑定存档，不再需要 `<世界>` 层。迁移细节见 §15。

**目标语义**：本次倒流恢复的是「上次删块完成之后 到 本次倒流开始」之间记录的全部方块类型变化。

- **记录常开**：服务器启动即写入 `config/samsara/diff/live/<世界>/`（`DiffRecorder.initWorld`）；周目 end/倒流完成都**不停止**记录。
- **窗口命名**：常开窗口 `live`（含义是"常开记录窗口"，**不是**"当前世界"）；冻结恢复源 `cycle<周目id>`。旧名 `current`、`s<周目id>` 在启动时（及打开恢复源前）**幂等迁移**：目标已存在则按文件合并，绝不覆盖/丢弃 `.dat`。
- **冻结**：倒流真正启动时（`RewindEngine.start` 扫描成功后）把当前世界层 `live/<世界>` **冻结**为 `diff/cycle<周目id>/<世界>/` = 本次倒流的**恢复源**，同时开启新 `live`；其他世界的数据留在 `live`。
- **重置**：倒流完成、物理删除执行时**重置窗口**（丢弃倒流期间改动——它们属于倒流开始前的世界状态）；**中止不重置**（窗口继续累计，下次倒流仍可见）。`rewind=0`/new-world 不触发冻结/重置（窗口自然延续）。
- **恢复源只读**：恢复调度器读 `diff/cycle<N>/<世界>`，记录写 `live/<世界>`，互不干扰 → 倒流期间的新改动不会被本轮倒流恢复（避免"今天建明天消"）。
- **维度隔离**：每个维度写入独立目录 `diff/live/<世界>/<命名空间>/<维度路径>/`（如 `world/minecraft/overworld/`、`world/minecraft/the_nether/`），冻结后同样保留世界/维度层。恢复侧当前只读主世界，下界/末地的记录保留供未来多维度倒流使用，不会与主世界同坐标碰撞。旧版无维度/无世界布局在启动时依次迁入 `<世界>/minecraft/overworld/`。
- **落盘**：`live` 每 30 秒与停服时 flush；冻结、重置、中止合并前强制 flush。避免重启/强杀丢掉最近一段方块变化。
- **中止合并**：中止倒流时把 `diff/cycle<周目id>/<世界>/` **并回** `live/<世界>`（不是保留一个独立冻结库），保证“中止不重置”在下一次倒流时仍然成立。
- **恢复源清理**：倒流完成并归档后删除 `diff/cycle<周目id>/<世界>/`，避免按周目无限累积；中止时已并入 live。
- **fake 注入目标**：倒流进行中 → 恢复源 `diff/cycle<N>/<世界>`（倒流可见）；否则 → `live/<世界>`（下次倒流可见）；注入后恢复侧重新读盘。

### 11c.3 轨迹事件 `.evt`

```

记录：dt varint（距上一条事件毫秒） + type(1B) + payload
```

| type | 名称 | payload |
|---|---|---|
| 0x01 | `EQUIP` | 槽位 bitmask(1B) + 每个槽 `len varint + NBT bytes`（len=0 为空） |
| 0x02 | `SWING` | 手(1B) + 动画 id(1B) |
| 0x03 | `USE_START` | 手(1B) |
| 0x04 | `USE_STOP` | 无 |
| 0x05 | `INVENTORY` | 可选完整背包；`len + NBT` |
| 0x06 | `BLOCK_BREAK` | 预留 |

- 槽位顺序固定：主手、副手、头、胸、腿、脚；另加选中槽（0~8）。
- 物品编码：`ItemStack.CODEC` + `RegistryOps.create(NbtOps.INSTANCE, registryAccess)`；解码在主线程。
- 首条事件必须是 `EQUIP`（新段初始快照），保证 `equipmentAt(t)` 有基线。
- 尾部不完整：读到最后一个完整记录为止并 WARN；不影响 `.bin`。

## 12. 倒流删除：待删队列与兜底、术语（用户 2026-08-17）

**术语（用户反馈"已到点"难懂，统一如下）**：
- **倒流时刻**（rewindAtMs）：未圈地块的"退场时刻"。2026-10-28 起统一设为倒流时长终点（加载中的区块本来就不能提前强删；运行期由双光标逐格恢复，退场/删块在终点执行）；
- **已到倒流时刻**（原"到点/已标记"）= 该区块应退场（删除重生成）；
- **退场** = 备份 + 清零槽位，重启后按当前版本重新生成；
- **待删队列**（`pending-delete.json`）= 完成时仍加载、不能立即删除的"已到倒流时刻"区块。

**删除兜底（H1/H2 修复）**：
1. 完成删除时：**已卸载**区块 → 后台线程备份 + 清零（不卡主线程）；**仍加载**的区块**不强制卸载、不删除**，记入待删队列；
2. 待删队列：区块**卸载即删**（`CHUNK_UNLOAD` 钩子）；服务器启动（`SERVER_STARTED`）与停服（`SERVER_STOPPED`）窗口**兜底清空**——常驻加载的出生区块最终也能删除；
3. 入队 / 删除前**复查保护集**：期间新圈地的区块取消删除；
4. **幂等**：仅处理仍存在于磁盘的区块（`McaRegion.chunkExists`），已清零不重复备份；备份按区域文件去重；
5. 中止倒流 = 一切保留：不从队列删任何区块（队列一并丢弃）；
6. 归档：倒流"走完"（传送完成 && 恢复完成）后把 `rewind.json` 归档至 `config/samsara/archive/`（不删除，供审计）；中止仍清除；
7. **文件级回收（用户 2026-08-17）**：删除不止清槽位——清零后 **1024 槽全空的 .mca 直接整文件删除**（MC 视缺失=空，行为一致）；**停服窗口自动执行区域文件瘦身 `compact`**（`/samsara debug rewind compact` 可运行中手动触发，被占用文件跳过）：全空文件删除 + 部分有效文件备份后**压缩重写**（只保留有效区块数据，丢弃孤儿扇区，真正回收磁盘空间）。压缩前备份到 `config/samsara/backups/compact_<时间戳>/`。

## 16. 活动记录：静默采集约定（2026-10-27 重构）

- **统计增量**：`leave.stats` = 退出时原版统计 − 加入时原版统计，直接读内存中的 `ServerStatsCounter`（无磁盘 I/O）；缺省键为 0。
- **开销**：**无** tick 轮询或周期采样；仅登录、退出、启停各一次追加写（加入/退出各一次统计求和）。停服窗口给在线玩家补写 `leave`。
- **崩溃语义**：`join` 无对应 `leave` 即上次会话被强杀；消费方以 `server_stop` / 下一条 `server_start` 为界截断。
- **不再写入** `activity.log`（旧格式）；旧文件可直接删除，`tools/analyze.py` 仍兼容读取。

## 18. 批量优化模式（用户 2026-08-26 确立，适用于所有大批量查找/删除操作）

**核心原则**：不只是 MCA 文件——任何需要大量查找/删除的操作都应遵循此模式。

### 18.1 五步优化

| 步骤 | 机制 | 示例 |
|---|---|---|
| **1. 按分组键聚合** | 将操作按"组"聚合（dimRoot、region 文件、玩家等），每组只做一次 I/O | `drainNonLoaded` 按 dimRoot 分组 → 每维度一次 `McaRegion.deleteChunks` 调用 |
| **2. 预构建索引** | 提前计算每组的"跳过/决策信息"，避免逐项检查 | `getWhitelistCountByRegionFile` 构建 `Map<文件名, 白名单区块数>` |
| **3. 快慢路径分离** | 索引命中快路径（如 0-wl 文件 → 整文件秒删）；未命中走慢路径（读 header + 逐项检查） | `deleteChunks` 3 参数版：`wlCount==0` → `Files.deleteIfExists`；`wlCount>0` → 读 header + 比较 |
| **4. 去重** | 按唯一键去重（Set/Map），避免重复操作 | `backedUp` Set 按 RegionPos hash 去重，不重复复制 |
| **5. 两级过滤** | 先粗筛（索引/目录级），再细筛（逐项检查） | SafeDeletion：先看整个 region 文件有无白名单（粗），再看每个 slot 是否在白名单内（细） |

### 18.2 适用场景

- **MCA 文件批量删除**：按 dimRoot 分组 → 按 region 文件分组 → 索引快删 + 混合删。
- **磁盘扫描**：先扫目录结构（粗），再读文件头（细）。
- **数据索引查询**：预构建 `Map<Key, Value>`，查询 O(1) 而非 O(n)。

### 18.3 注意

- 索引可以是"惰性构建"（首次使用时构建，缓存到 Map）。
- 快路径失败时**回退到慢路径**，不中断流程。
- 去重可以用 RegionPos hash、文件路径、坐标 key 等任何唯一标识。

## 19. MC 26.2/26.3 API 注意事项（2026-08-26 补充，2026-10-27 更新）

### 19.1 ResourceKey.toString() 格式

MC 26.2 的 `ResourceKey.toString()` 返回 `"ResourceKey[minecraft:overworld]"` 格式，**不是** `"minecraft:overworld"`。解析时需用 `lastIndexOf(':')` 和 `lastIndexOf('[')` 提取 namespace 和 path。

```java
// 辅助方法（RewindEngine.parseResourceKey）
private static String[] parseResourceKey(String keyStr) {
    int colonIdx = keyStr.lastIndexOf(':');
    if (colonIdx < 0) return null;
    int nsStart = Math.max(keyStr.lastIndexOf('[', colonIdx), keyStr.lastIndexOf(' ', colonIdx)) + 1;
    String ns = keyStr.substring(nsStart, colonIdx);
    int dimEnd = keyStr.length();
    for (int i = colonIdx + 1; i < keyStr.length(); i++) {
        char c = keyStr.charAt(i);
        if (c == ' ' || c == ']' || c == '>') { dimEnd = i; break; }
    }
    String dim = keyStr.substring(colonIdx + 1, dimEnd);
    return new String[]{ns, dim};
}
```

### 19.2 Level.NETHER / Level.END 不存在

MC 26.2 中 `Level.NETHER` 和 `Level.END` **不是静态字段**，只有 `Level.OVERWORLD`。获取其他维度的 ResourceKey 需要通过反射扫描 `Level.class.getDeclaredFields()`，或通过路径/RegistryKey 推断。

### 19.3 Level.setBlock 变成 4 参数（26.3）

MC 26.3 起 `LevelAccessor` 的 3 参数 `setBlock(pos, state, flags)` 是 **default 方法**，实际实现是
`Level.setBlock(pos, state, flags, recursionLeft)`。Java 代码里的 3 参调用仍然可用（走 default），
但 **Mixin 必须注入 4 参数版本**；继续注入 3 参签名会在启动时报
`InvalidInjectionException: could not find any targets matching 'setBlock(...;I)Z'`。

现行写法：`ServerLevelMixin` 注入
`setBlock(Lnet/minecraft/core/BlockPos;Lnet/minecraft/world/level/block/state/BlockState;II)Z`，
方法参数为 `(BlockPos pos, BlockState newState, int flags, int recursionLeft, CallbackInfoReturnable<Boolean> cir)`。

## 21. 配置与数据分层约定（2026-10-30）

- **路径解析统一入口**：`StoragePaths`（或等价类）负责 `configRoot`、`worldDataRoot`、`globalDataRoot` 与迁移；禁止各模块自行拼 `FabricLoader.getConfigDir()`。
  - `configRoot = FabricLoader.getConfigDir()/samsara`
  - `worldDataRoot = server.getWorldPath(LevelResource.ROOT)/samsara`（`storage.yml` 可覆盖）
  - `globalDataRoot = storage.globalFollowWorld ? worldDataRoot/global : FabricLoader.getGameDir()/samsara/global`（`storage.yml` 可覆盖）
- **全局数据开关**：`storage.globalFollowWorld` 默认 `true`（随存档）。切换时 `StoragePaths` 先在旧/新根之间迁移再切换，双向都支持；迁移期间暂停身份/认证读写，失败回滚并保持原开关值。
- **只写自己的层**：配置模块写 `configRoot`；世界模块写 `worldDataRoot`；身份组配置写 `config/samsara/identity.yml`，身份数据/同步状态/审计写 `<主存档根>/samsara/identity/`（随主存档复制/备份，不随世界栈/`globalFollowWorld` 切换）。跨层写入视为缺陷。
- **YAML**：配置文件一律 `.yml`，用 SnakeYAML 2.x（JiJ）；禁止用 Gson 写配置。JSON/JSONL 只用于旧版迁移、活动/审计日志、轨迹事件等机器格式。
- **schema 驱动**：每个配置项必须在 `ConfigSchema` 注册（类型、默认值、范围、说明、分组、是否重启）；加载、生成、Web 表单、校验共用。新增配置不得只写一个字段而不注册 schema。
- **完整生成**：首次启动写出全部键（含默认值）和注释；缺键读取默认值；非法值回退 + `WARN`；保存原子写 + `.bak`。
- **敏感值**：Web token 不得明文写进 `commands.yml`，token 放 `web.yml`。v0.20 起身份组不再保存密码；v0.19 的 `auth.yml` 在迁移时归档，认证由其他模组负责。
- **身份写入备份**：`identity.yml` 原子写 + `.bak`；玩家数据同步前保留 `.bak` 并写 journal；身份重绑/迁移前复制到 `identity/archive/`；失败不删源数据。
- **迁移**：必须幂等、先备份、失败不删源、写版本标记；迁移代码单独成类，单测覆盖“全新安装 / 旧 JSON / 旧数据目录 / 已迁移 / 迁移失败”。

## 22. 本地 Web 约定（2026-10-30）

- **只监听回环**：`127.0.0.1`，首版不提供 `0.0.0.0` 开关；不得把面板暴露到公网。
- **鉴权**：启动生成 32 字节随机 token，写 `web.yml` 并打印到控制台；API 要求 `Authorization: Bearer`，常量时间比较；不接受 URL 查询参数传 token（避免日志泄漏）。
- **绑定生命周期**：`SERVER_STARTED` 启动，`SERVER_STOPPING` 停止；端口占用时记录 `WARN` 并继续启动服务器，不阻塞主流程。
- **API 只做配置**：首版只提供 schema/值/校验/保存/重载/状态；不得通过 Web 删改世界数据、执行命令或上传文件。
- **输入校验**：请求体限长、字段类型/范围由 schema 校验；错误返回字段级信息；保存前先校验，校验失败不落盘。
- **静态资源**：全部打包在 mod 内，不引用 CDN；页面不执行用户输入的 HTML（用 `textContent`，不用 `innerHTML`）。
- **日志**：只记录方法/路径/状态码与耗时，不记录 token、请求体中的敏感值。
- **测试**：schema 校验/YAML 往返单测；本地 HTTP 集成测试覆盖鉴权失败、非法值拒绝、保存成功、重载、端口占用降级。

## 23. 身份组与宠物多主人（v0.20）

### 23.1 身份组模型

- 配置：`config/samsara/identity.yml`（服务器级，不随世界栈切换）。
- 字段：`identity.enabled`（默认 false）、`identity.syncPlayerData`、`pets.maxOwners`、`groups[].name/data/premium/offline/note`。
- `data` 是数据 UUID，可以不是任何玩家账号；不在组里的玩家隐含 `data = 自己 UUID`。
- `premium`/`offline` 各自最多一个；同一 UUID 不能出现在多个组。
- 不做身份组锁定；前提是正版服/盗版服互斥，同组不会同时出现正版和离线账号。若未来代理/混合模式允许同时登录，必须重新加锁。

### 23.2 归属策略（硬约束）

> 归属/事件数据写实际 UUID；查询、权限、统计、同步时解析到 data UUID。

- 圈地、周目分组、待传送、轨迹、活动、宠物 owner 均写实际 UUID。
- 读取/比较/统计时统一走 `identityOf(uuid)`。
- 新数据不得强制写 canonical；旧数据不改写。
- 玩家数据是唯一例外：按 `data UUID` 存独立文件。

### 23.3 账号切换同步

- 运行时状态：`<主存档根>/samsara/identity/state.json`（`dataUuid`/`lastWriter`/`sync-blocked`）。
- 同账号重连不同步；账号切换时 `data ↔ 当前账号`。
- `lastWriter` 为空时，用当前账号数据初始化 data。
- 数据文件：`<主存档根>/samsara/identity/playerdata/<dataUuid>.dat` + advancements/stats。
- 业务失败拒绝同步；技术失败 journal + `.bak` + 原子替换，启动时恢复，不删源数据。

### 23.4 Web 身份组编辑

- 独立页面/API，不复用普通扁平配置表单。
- 校验：UUID 格式、跨组唯一、canonical/data 关系、组名唯一。
- 预览：圈地数量、playerdata、轨迹/活动聚合、在线状态。
- 修改 `data` 必须走“重绑数据存储”：预览、二次确认、备份、复制/移动、更新 state、审计；新 data 已有数据时默认拒绝，禁止静默覆盖。

### 23.5 宠物多主人

- 保留原版 `Owner` 标量；额外主人写入 `samsara:owners` 列表；原版忽略未知 tag，不报错。
- `TamableAnimalMixin`：读写额外列表、`isOwnedBy` 多 owner、`tame`/`setOwner` 追加。
- 所有主人拥有主主人权限；冲突时主主人优先。
- 跟随：主主人 → 手持驯服物品的最后持有者 → 最近在线主人 → 等待。
- 任何玩家用对应驯服物品右键已驯服宠物即可加入 owner；同一身份组按 data 去重；上限 `pets.maxOwners`（默认 32）。
- 纯原版保存可能丢失额外主人，主主人保留；这是可接受降级。

### 23.6 退役项

v0.20 删除：`register/login/password`、`bind-premium`、`reset-pw/kick/migrate/rollback`、密码数字键盘、`auth.yml`、Argon2id、LoginThrottle、IP 限流、身份组锁定。
