# 计划：存储布局按「生命周期」重组（G-02 第二批）

> 2026-11-18 提案。当前只讨论**业务语义**，不改代码；需要服主拍板后才会进入实现。
> 第一批（代码层收敛）已完成：路径统一由 `StoragePaths` 解析，见 `7943b3e`。

## 1. 现在的问题（不是技术问题，是语义问题）

1. **`config/` 被当成“服务器级杂物间”**：`gold-price.json`（经济数据）、`season-advance.json`（周目进度）、`announcements.json`（公告历史）和真正的配置 YAML 混在一起。服主分不清哪些能手改、哪些改了会被覆盖。
2. **周目重置后哪些数据该活下来，没有明确规则**：圈地、容器、乐透轮次都在 `world/samsara/`，换周目即消失；身份/背包在独立目录，跨周目保留。这个差异是历史形成的，不是设计出来的。
3. **大文件与世界存档绑死**：轨迹、活动日志、地图数据都在 `world/samsara/`，每次备份世界都要复制一遍，周目越多、备份越慢、磁盘越占。
4. **调试备份写进玩家存档**：`debug claim delete backup` 落在 `world/samsara/backups/`，会被世界备份一并打包，也容易被当成玩家数据误删。
5. **`globalFollowWorld` 开关让同一份数据有两个可能位置**：服主点一下，数据搬家；搬一半失败就出现“两份数据、不知道哪份是新的”。业务上不值得给这个选项。

## 2. 建议：按“活多久 / 跟谁走”分四类

| 类别 | 放什么 | 换周目 | 进世界备份 | 服主可手改 |
|---|---|---|---|---|
| `config/` 服务器配置 | 权限、命令、Web、输出模板、各种开关 | 保留 | 不进（单独备份） | ✅ 可以 |
| `data/` 服务器数据 | 经济价格、公告历史、审计、轨迹、地图缓存、调试备份 | 保留 | **不进** | ❌ 不要动 |
| `world/samsara/` 存档数据 | 圈地、容器索引、当前周目状态、当前乐透轮次、出生点历史 | 随周目重置/归档 | 进 | ❌ 不要动 |
| `players/` 玩家数据 | 身份映射、背包、余额、待领取 | **保留** | 单独备份 | ❌ 不要动 |

一句话：**玩家数据跨周目，存档数据随周目，历史数据不随存档，配置永远在顶层。**

## 3. 需要你拍板的 5 件事

1. **换周目后圈地怎么办**：直接清空 / 归档到 `data/archive/claims/<周目>/` 后清空？（现在是清空，没有归档）
2. **轨迹要不要跨周目保留**：保留则移出 `world/`，旧周目回看仍然可用；不保留则跟周目一起归档。
3. **乐透奖池/保险基金是否跨周目滚存**：现在跟 world 走，换周目等于清零；如果要滚存，必须移到 `players/` 或 `data/`。
4. **是否接受“轨迹/地图/审计不再随世界备份”**：世界备份会显著变小变快，但这些数据要单独备份一次。
5. **是否关掉 `globalFollowWorld` 开关**：建议固定为“服务器级”，UI 里只读显示位置，避免误切造成数据分裂。

## 4. 如果同意，实施顺序

1. 先只改**新数据**的落点，旧数据原地不动（不迁移、不破坏）。
2. 加布局版本号，启动时只做一次“旧位置 → 新位置”的移动，失败则原地保留并告警。
3. 中间给一个只读的“存储布局”页：显示每类数据在哪、多大、最近写入时间，方便确认迁移结果。
4. 迁移完成且稳定一个版本后，再清理旧路径代码。

## 5. 明确不做

- 不为了“看起来整齐”搬迁运行中的世界数据。
- 不在没有备份的情况下自动删除任何旧目录。
- 不让 Web 页面直接写 `data/` 下的历史文件。
