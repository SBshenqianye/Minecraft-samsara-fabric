## 1. 区块管理

### 1.1 旗帜圈地（白名单）

**用户故事**：作为玩家，我希望通过放置旗帜来保护我的建筑区域，使其在版本更新时不会被删除。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-01 | 玩家放置带方向图案+图标的旗帜 | 识别为圈地旗，注册为节点 |
| F-02 | 同一方向被多个图案叠加 | 每个方向取最大值 |
| F-03 | 旗帜被拆除 | 其区域从并集中移除 |
| F-04 | 多个旗帜区域重叠 | 保护区域 = 所有旗帜区域的并集 |
| F-05 | 玩家右键已放置旗帜 | 显示方向+距离+所属圈地区域信息 |
| F-06 | 非主人或非 OP 拆除旗帜 | 拒绝拆除 |
| F-143 | 服主调整圈地保护范围 | 可按染料颜色分别设置延伸距离，也可切换为固定距离、为 15 种图案分别配置单位方向，并设置单方向上限；图案只定方向、颜色只定长度；保存后已有圈地立即按新范围重算；Web 使用独立“圈地范围”标签页，提供 4×4 颜色浮窗色板、统一设值、带预览的图案网格/朝向切换、保护形状实时预览与可拖放多面旗帜的调试画布；**单面旗帜只生成图案射线，所有旗帜的射线汇总后才做全局“化线为面”，只有多面旗帜围出的闭合区域才进入保护**；切换固定/染料模式后条件项与左侧导航立即显隐；画布支持连续缩放与拖拽平移 |

### 1.2 区块删除

**用户故事**：作为管理员，我希望在版本更新后自动删除未保护的旧区块，让新结构就近生成。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-07 | 执行删除前 | 必须有 dry-run 预览 |
| F-08 | 删除执行时 | .mca 级备份 + 整档 zip |
| F-09 | 已加载区块 | 卸载即删（CHUNK_UNLOAD 钩子） |
| F-10 | 未加载区块 | 后台线程备份+清零 |
| F-11 | 全空 .mca 文件 | 整文件删除 |
| F-12 | 停服窗口 | compact 压缩重写残留文件 |

## 2. 世界与轮次（原「周目」）

> **2026-11-01 v0.24 模型更新**：`world` 固定是栈顶/最新；旧世界是 `world/dimensions/samsara/stack_<n>` 自定义维度，不再使用服务器根下的 `world_sN` 兄弟文件夹。数字越大越新，`world` 本身最新。玩家数据 `world/players/` 共享；`dimensions/<dim>/data`、claims、track 按栈隔离。

> **2026-10-31 模型修订**：不再用「注册周目 → 开始周目」的两段式流程。
> **世界 = 文件夹**，**周目 = 出生点历史中的一段（当前轮）**。玩家可见文案用「世界 / 栈 / 出生点 / 新一轮」，
> 不要求用户先创建周目。旧 `season.json` 只作为出生点历史/日志迁移来源。

### 2.1 世界文件夹与栈

**用户故事**：作为服主，我把已有世界文件夹放进服务器目录，服务器就能自动识别它，不需要注册。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-13 | 服务器启动时发现含 `level.dat` 的世界文件夹 | 自动识别为栈层；无需 `/season create` |
| F-14 | 栈顺序 | 按自然入栈顺序（`world` → `world_s1` → `world_s2` …）固定，不因最后活动时间/当前所在世界重排 |
| F-15 | 世界身份 | 每个世界在自己的 `samsara/stack.json` 保存 `index/parent/worldId/createdAt`；移动/备份单个世界不丢顺序 |

### 2.2 出生点历史与「新一轮」

**用户故事**：作为玩家，我希望同一个世界里换出生点后，状态能自动把它当成新一轮，而不是依赖管理员先注册。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-144 | 世界首次发现 | 在 `samsara/spawn-history.json` 写入第 0 条 `initial` 出生点 |
| F-145 | 启动时 `level.dat` 出生点与最后一条距离 > 16 格 | 自动追加 `detected`，当前轮随之变化 |
| F-146 | 旧 `season.json` 有出生中心 | 一次性迁移为只读出生点历史；迁移有日志，旧记录不再驱动流程 |

### 2.3 开新一轮的两个动作

**用户故事**：作为管理员，我只需要两个动作：同世界重置，或新建世界入栈。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-16 | 同世界重置 | 任意栈层可执行：保留保护区块，倒流并物理删除该层未保护区块；用排斥算法选新出生点，传送当前在该层的玩家、设置个人重生点、追加该层出生点历史；只有栈顶同时更新世界重生点 |
| F-17 | 新世界入栈 | 新建独立世界（独立种子/下界/末地），旧世界原地保留在栈下层，全员迁移；`archiveData=true` 时只归档旧 `data/minecraft`，运行期所有栈共享当前 data |
| F-18 | 新世界入栈 | 仅允许当前世界是栈顶时执行 |
| F-147 | 排斥点 | 新出生点与所有历史出生点保持最小间距；间距随历史数量小幅增长；优先避开海洋/岩浆/陡坡/保护区；无法落脚时生成安全落脚点 |
| F-148 | 连续重置 | 连续多次同世界重置后，出生点不聚集，历史按顺序累加 |
| F-149 | 状态查询 | 显示当前世界、当前轮、出生点、历史数量，不依赖注册记录 |

### 2.4 分组出生

**用户故事**：作为玩家，我希望开新一轮时能和朋友分组分散出生，避免开局挤在一起。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-19 | 分组大小 | 3~5 人/组 |
| F-20 | 组间距离 | ≥ groupMinDistance |
| F-21 | 出生点围绕出生中心 | 极角均分 + 随机抖动 |
| F-22 | 持久化 | 出生点写入当前轮的分组数据（内部日志；用户流程以出生点历史为准） |

## 3. 时间倒流（逆熵引擎）

### 3.1 概念

**用户故事**：作为玩家，我希望未圈地区域能"逐格地"回到新生成时的模样，体验"逆熵"仪式感。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-23 | 倒流周期 | **可配置，默认 26 小时**；周目边界随之逐季漂移（使固定时刻上线的玩家在多个周目内看到倒流的各个阶段） |
| F-24 | 记录范围 | 记录玩家破坏/放置、爆炸导致的方块变化 |
| F-25 | 不记录范围 | 不记录红石、作物生长、流体流动等世界模拟噪声 |
| F-26 | 倒流期间新改动 | 不受影响（快照语义） |
| F-27 | 圈地暂停 | 倒流期间玩家圈地的区块立即暂停倒流 |
| F-28 | 倒流完成 | 自动执行物理删除 |

### 3.2 倒流节奏（近慢远快）

**用户故事**：作为在场玩家，我希望倒流时身边的方块变化慢一些、能看清细节；远处的世界则快速退场——因为看倒流的兴致集中在刚开场那段时间。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-64 | 玩家附近的区块 | 以更慢的节奏退场，进度落后于远处，供玩家就近观察 |
| F-65 | 距玩家 4 区块以外的区块 | 按更快曲线退场，允许早于总时长完成 |
| F-66 | 近处区块落后时 | 不参与"倒流是否完成"的判定；退场、传送、删块一律以远处（权威进度）为准 |
| F-67 | 玩家进入/离开近处 | 离开后该区块在数秒内（斜坡）追平权威进度；进入时从当前权威进度开始慢放，不回退 |

### 3.3 玩家轨迹记录与回放

**用户故事**：作为玩家/管理员，我希望服务器留档"谁在什么时候走过哪里"，并能以游戏内可见的人形回放，用来回顾上一周目发生过什么。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-68 | 记录内容 | 在线玩家的位置与朝向，按固定频率采样（默认 5Hz）；写入频率不随记录年龄变化 |
| F-69 | 回放形式 | 以游戏内可见的人形实体呈现；其他玩家**无需安装额外模组** |
| F-70 | 回放时间轴 | 与倒流共用同一条时间轴（回放位置与方块恢复进度对应） |
| F-71 | 保留策略 | 记录越老采样越稀，直到下限；任何年龄的记录都不被整体丢弃（远期至少保留骨架） |
| F-72 | 存储上限 | 总量有上限，不随运行时间无限增长 |

### 3.4 人偶捕捉与多人同屏回放

**用户故事**：作为在场玩家，我希望回放的人偶像真实玩家一样可以被攻击、被抓住，也能同时看到多个玩家的回放。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-73 | 回放实体形态 | 原版人形（26.3 `Mannequin`），客户端无需安装模组；能显示玩家皮肤 |
| F-74 | 多人同屏 | 可同时回放多个玩家/多个目标，所有在场玩家都能看到全部人偶；每个回放独立推进、独立结束 |
| F-75 | 玩家攻击/交互人偶（第一次） | 立即停止该回放、取消本次伤害、人偶停在原地，不再沿轨迹移动 |
| F-76 | 捕捉后的轨迹 | 该玩家在该周目从捕捉时刻起的轨迹不再参与任何回放（磁盘记录保留）；其他玩家/周目不受影响 |
| F-77 | 捕捉后的人偶 | 变成普通实体：无 AI、不会自己走，有重力/碰撞，可被攻击/杀死，可被推动/活塞/拴绳搬运，不因距离自然消失 |
| F-78 | 捕捉与方块逆熵 | 不保护人偶所在区块、不写 `trophies.json`、不做区块删除后重建；方块照常逐格恢复与删块 |

> **有意行为**：人偶留在会被删除的区块里会随区块一起消失；玩家在倒流结束前把它运到不会被删的区块（已圈地、扫描范围外的新出生区或其他维度），它才能活到下一周目。

### 3.5 回看模式（只读回放）

**用户故事**：作为玩家/管理员，我希望**随时**回看某位玩家在任意时间段的轨迹，像看一段录像；看的时候世界不受影响，看完（或中途停止）后我和世界都回到开始前的样子，不留任何痕迹。

**与 3.4 的分工**：3.4 的回放是"参与型"——人偶可被捕捉、会截断该玩家后续轨迹、捕捉后会留在世界里；3.5 是"只读型"——只用来看，不产生任何持久后果。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-79 | 入口 | 开始回看、停止回看、查看回看状态、查看某玩家可回看的时段；开始命令接受目标玩家与开始时间 |
| F-80 | 参数 | 至少支持：倍速（0.1~64）、结束时间或时长、循环、是否跟随、是否临时旁观、是否发光/显示名牌、显式指定周目、自动瞄准、时间轴跳转；非法参数给出明确原因且不改变任何状态。回看人偶**不再提供“可交互”开关**（见 F-94/F-95） |
| F-81 | 只读承诺 | 回看全程**不写任何磁盘数据**（轨迹、差异、捕捉截断点、人偶存档、周目数据均不变），也不触发轨迹保留扫描/降采样 |
| F-82 | 不捕捉 | 回看中**不存在**攻击/交互人偶的路径；即使误触也不触发捕捉、不写截断点、不广播、不缩小该玩家后续可回放的范围 |
| F-83 | 始终不可交互 | 回看人偶无碰撞、不可攻击、不可推动、右键不接管、不触发压力板/绊线/幽匿感测体等触发元件；旁观者左键只用于相机接管（见 F-95），不产生世界交互 |
| F-84 | 结束即恢复 | 回看结束（播完 / 手动停止 / 观看者退出、死亡、换维度 / 服务器停止 / 异常）后，观看者的维度、坐标、朝向、游戏模式、飞行与无敌等能力全部恢复到开始前 |
| F-85 | 无残留 | 结束后移除人偶、释放临时加载的区块、清理进度条/计分板/队伍/临时效果等展示物；不产生新的存档实体 |
| F-86 | 世界零副作用 | 回看不改变方块、实体、时间、天气与怪物生成；不保护/不删除区块；不参与逆熵 |
| F-87 | 多人并发 | 多人可同时回看同一或不同目标，各自独立进度与参数；同一观看者重复发起时替换上一次，而不是叠加 |
| F-88 | 时间与周目 | 开始时间支持 epoch 毫秒、`yyyy-MM-dd`、`HH:mm`、`yyyy-MM-ddTHH:mm`；未指定周目时按开始时刻反查；跨天/同周目多段自动拼接；跨周目默认拒绝，需显式指定 |
| F-89 | 失败安全 | 目标无记录、文件损坏/截断、周目不明、超出加载或并发上限时，拒绝开始并说明原因与可用时段；观看者状态不变 |
| F-90 | 权限与审计 | 回看自己的记录=所有人；回看他人=管理员；每次回看他人记录留下审计（谁、看谁、周目、时间窗、倍速、时长、结果） |
| F-91 | 可观测 | 状态入口显示目标、来源周目/日期/文件、进度、剩余时长、当前倍速；日志记录开始、结束与失败原因 |
| F-92 | 与捕捉式回放互斥 | 同一目标已有捕捉式回放进行中时，回看不接管、不并行，提示先停止；两类回放的实体与数据互不影响 |
| F-93 | 与捕捉截断的关系 | 回看同样遵守已有捕捉截断（被截断之后的轨迹不播），不提供绕过开关——保持 F-76 的承诺对"任何回放"都成立 |
| F-94 | 三种模式的交互边界 | 回看人偶**始终不可交互**；捕捉式回放（含开新周目时的回放）保持可捕捉、可推动、可搬运；方块倒流期间世界与方块照常可交互。三者语义不混用 |
| F-95 | 旁观观察人偶 | 观看者可左键把人偶作为旁观相机目标（只切相机，不攻击/不捕捉）；可退出观察；会话结束或人偶移除前先把相机归还观看者 |
| F-96 | 一键对齐 | 与暂停/继续同级的“对齐”按钮/命令：单目标贴到理想观察点并面向人偶；多目标对齐到场景中心或显式指定的跟随目标；不改变跟随开关 |
| F-97 | 群组时段回放 | 只给开始时间、不给目标时，默认回放该时段**有轨迹的全体玩家**；给出逗号分隔多目标时只回放这些目标；仍受管理员权限、并发与样本上限约束 |
| F-98 | 多目标镜头 | 两个及以上目标时**默认不强制跟随**；可用显式参数指定跟随其中一个；单目标保持现有跟随默认 |
| F-99 | 同目标去重 | 多个观看者回看同一目标且轨迹时间相差在阈值内时，只渲染一个人偶；时间偏离、参数冲突或主会话结束后自动分裂/提升，不出现重复实体 |
| F-100 | 自动瞄准 | 可选、可即时开关；以视线中心为内圈死区，越接近外圈修正越快；只改视角不改位置；参数可配，非法值拒绝且不改变状态 |
| F-101 | 时间轴跳转 | 支持绝对时间、相对时间（如 ±30s）、百分比跳转；播放/暂停时立即生效；不越过窗口与捕捉截断 |
| F-102 | 进度调节输入 | vanilla 旁观模式不向服务端发送普通滚轮，且**不安装任何客户端模组**；服务端提供可点击步进/百分比/`seek` 命令，并提供“拖动模式”（A 后退 / D 快进 / 空格暂停 / Shift 加速，读取客户端本来就会发送的移动输入）。滚轮与真拖动条不做 |
| F-103 | 片段收藏 | 可对任意玩家轨迹切片收藏（起止、可选标签）；列表可查看/跳转/删除；自己的收藏所有人可用，他人的收藏需管理员；单段长度与数量有上限 |
| F-104 | 收藏保留保护 | 收藏区间在保留降采样中保持原采样密度；**不改变样本时间戳、不写 diff、不影响倒流与方块恢复**；仍遵守捕捉截断；保护带来的额外体积计入存储上限 |

| F-110 | 倒流留言 | 倒流期间把该周目窗口内的玩家发言以全息文字留在发言位置；按倒流进度渐显/渐隐；结束后清理，不写存档、不为显示而加载远处区块 |

> **有意行为**：F-84 只恢复**观看者自己**（位置/模式/能力）；世界从未被修改，因此不存在"回滚世界"的动作。若观看者中途被其他系统传送或改模式，以其当时状态为准，不强行覆盖回历史值。
>
> **术语**：本节称"回看"，3.4 称"回放"。两者是两条独立管线：回放=参与型（可捕捉、会截断、会留档），回看=只读型（零写入、零残留）。
>
> **2026-10-30 扩展**：3.5 从“单人只读回看”扩展为“单人/群组只读回看 + 片段收藏 + 装备/动作 + 聊天留言”。回看仍不写盘；新增的片段、事件、聊天写入只发生在**录制、收藏、发言记录**等显式路径，不属于回看会话。
>
> **“全息留言”的边界**：倒流是方块级全局倒流，不播放玩家轨迹；留言只借发言坐标与时间做展示，不参与方块恢复，也不影响 diff。

**用户故事**：作为服主，我希望在本地 Web 面板里可视化编辑游戏内命令/聊天输出，并且游戏内看到的效果与预览一致。

首批迁移的输出来源：`where`、`identity status`（含关闭/非法/未分组分支）、`claim info` 文本、`season status` 列表与汇总。其余命令保持硬编码，后续按同一模型扩展。

### 12.2 权限树

**用户故事**：作为服主，我希望在 Web 里按命令层级管理权限，关闭树干时自动关闭树枝和树叶，但不会误伤其他树枝。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-135 | 权限树完整 | 权限页按命令层级展示全部权限检查点、真实命令 literal 路径与中间节点；默认权限表的每一项都能在树中找到 |
| F-136 | 级联与独立 | 关闭树干会级联关闭所有后代；关闭树枝 A 不影响树枝 B；重新启用父节点后后代恢复原等级；叶子实际所需等级取路径上所有祖先与自身的最高等级 |

权限等级为 `user < op < owner < config < deny`。`deny`（“关闭权限”）高于 config/owner/控制台，任何来源都不能执行；为免把自己锁死，权限/配置/Web/重载等恢复路径仍保留控制台入口，Web 用感叹号提示。原“关闭”（boolean 停用节点）继续保留，但降级为次级按钮，负责级联停用后代，不改变等级。
