> **引用约定（2026-09-10 裁决）**：文档间与文档内引用一律使用「文档名 + 章节标题」，不使用章节编号。

## 1. 区块管理

### 1.1 旗帜圈地（白名单）

**用户故事**：作为玩家，我希望通过放置旗帜来保护我的建筑区域，使其在版本更新时不会被删除。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-01 | 玩家放置带方向图案+图标的旗帜 | 识别为圈地旗，注册为节点 |
| F-02 | 同一方向被多个图案叠加 | 每个方向取最大值 |
| F-03 | 旗帜被拆除 | 其区域从并集中移除 |
| F-04 | 多个旗帜区域重叠 | 保护区域 = 所有旗帜区域的并集 |
| F-05 | 玩家右键已放置旗帜 | 显示方向+距离+所属圈地区域信息 |
| F-06 | 非主人或非 OP 拆除旗帜 | 拒绝拆除 |

### 1.2 区块删除

**用户故事**：作为管理员，我希望在版本更新后自动删除未保护的旧区块，让新结构就近生成。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-07 | 执行删除前 | 必须有 dry-run 预览 |
| F-08 | 删除执行时 | .mca 级备份 + 整档 zip |
| F-09 | 已加载区块 | 卸载即删（CHUNK_UNLOAD 钩子） |
| F-10 | 未加载区块 | 后台线程备份+清零 |
| F-11 | 全空 .mca 文件 | 整文件删除 |
| F-12 | 停服窗口 | compact 压缩重写残留文件 |

## 2. 周目（Season）管理

### 2.1 周目生命周期

**用户故事**：作为管理员，我希望服务器能按"周目"运营，每个周目有独立的时间和出生中心。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-13 | 创建新周目 | 自动结束上一个周目 |
| F-14 | 始终有一个 ACTIVE 周目 | 不允许双 ACTIVE |
| F-15 | 记录每个周目的时间与出生中心 | 持久化到 season.json |

### 2.2 世界模式

**用户故事**：作为管理员，我可以选择 same-world（保留旧世界）或 new-world（新建世界）模式开新周目。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-16 | same-world 模式 | 时间倒流删除旧区块，新周目在同一世界 |
| F-17 | new-world 模式 | 旧世界备份入栈，新建世界，强制迁移 |
| F-18 | new-world 模式 | 仅允许栈顶世界执行 |

### 2.3 分组出生

**用户故事**：作为玩家，我希望开新周目时能和朋友分组分散出生，避免开局挤在一起。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-19 | 分组大小 | 3~5 人/组 |
| F-20 | 组间距离 | ≥ groupMinDistance |
| F-21 | 出生点围绕出生中心 | 极角均分 + 随机抖动 |
| F-22 | 持久化 | 出生点写入 season.json 的 groupSpawns |

## 3. 时间倒流（逆熵引擎）

### 3.1 概念

**用户故事**：作为玩家，我希望未圈地区域能"均匀地"回到新生成时的模样，体验"逆熵"仪式感。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-23 | 倒流周期 | 一天为周期 |
| F-24 | 记录范围 | 记录玩家破坏/放置、爆炸导致的方块变化 |
| F-25 | 不记录范围 | 不记录红石、作物生长、流体流动等世界模拟噪声 |
| F-26 | 倒流期间新改动 | 不受影响（快照语义） |
| F-27 | 圈地暂停 | 倒流期间玩家圈地的区块立即暂停倒流 |
| F-28 | 倒流完成 | 自动执行物理删除 |

## 4. 世界栈（多世界）

### 4.1 跨世界传送

**用户故事**：作为玩家，我希望通过游戏内的自然操作（突破基岩、搭方块到高处）在不同世界间传送。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-29 | 主世界突破基岩进入虚空 | 传送到同世界下界对应坐标 |
| F-30 | 下界突破基岩进入虚空 | 传送到下层世界主世界空中 |
| F-31 | 下界搭方块到 Y>255 | 传送到同世界主世界对应坐标 |
| F-32 | 主世界搭方块到 Y>320 | 传送到上层世界下界对应坐标 |
| F-33 | 连续传送 | 支持穿越世界栈的传送链 |
| F-34 | 栈底下界再往下掉 | 真正死亡（保留原版虚空掉血） |

## 5. 全员同意制

### 5.1 核心机制

**用户故事**：作为玩家，我希望没有管理员时也能通过在线玩家全员同意来开新周目。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-35 | 管理员（OP level 2+） | 可随时直接执行 |
| F-36 | 无管理员，在线 >1 人 | 任何玩家可发起 |
| F-37 | 发起后 | 需在线玩家全员同意 |
| F-38 | 48 小时内未达成 | 发起自动过期 |

## 6. 身份同步

### 6.1 核心功能

**用户故事**：作为玩家，我希望在正版/离线模式切换时保留我的圈地归属权和玩家数据。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-39 | 新玩家首次登录 | 提示注册密码 |
| F-40 | 已注册玩家登录 | 输入密码验证 |
| F-41 | 未验证状态 | 以观察者模式置于栈底世界，禁止交互 |
| F-42 | 登录/退出时 | 执行全状态同步（canonical ↔ 当前 UUID） |
| F-43 | 同组 UUID 同时在线 | 拒绝新登录（身份组锁定） |
| F-44 | 玩家获得 premium 账号 | 可通过 bind-premium 绑定到身份组 |
| F-45 | 管理员操作 | 可踢出离线 ID，归档其数据 |

### 6.2 密码策略

**用户故事**：作为管理员，我希望能配置密码策略以适应不同的安全需求。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-46 | minLength 配置 | 默认 8，可改为 1 |
| F-47 | storageMode 配置 | hashed（Argon2id）或 plaintext |
| F-48 | allowShort 配置 | minLength < 4 时需显式开启 |

### 6.3 安全防护

**用户故事**：作为管理员，我希望系统能防止暴力破解密码。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-49 | 单玩家每分钟 >5 次尝试 | 拒绝并提示等待 |
| F-50 | 连续失败 | 指数退避 10s → 160s |
| F-51 | 连续失败 10 次 | 封禁 15 分钟 |
| F-52 | 同 IP 每分钟 >10 次 | 拒绝 |

## 7. TPA 传送

**用户故事**：作为玩家，我希望通过指令请求传送到其他玩家或请求其他玩家传送到我。

**验收标准**：

| 编号 | 条件 | 预期行为 |
|---|---|---|
| F-53 | `/tpa <player>` | 请求传送到对方 |
| F-54 | `/tpahere <player>` | 请求对方传送到你 |
| F-55 | `/tpaccept` | 同意传送请求 |
| F-56 | `/tpdeny` | 拒绝传送请求 |
| F-57 | `/tpcancel` | 取消待处理请求 |
| F-58 | 请求发出 60 秒后 | 自动过期 |
| F-59 | 同时只能有 1 个待处理请求 | 新请求覆盖旧请求 |
