# samsara · 周目管理

> 原版红石生存服务器的**世界生命周期管理**：同一个存档，长期玩下去。
> **空间** 圈地保护 · **时间** 世界/出生点轮换 · **逆熵** 未圈地倒流重生 · **世界栈** 跨世界传送

## 当前版本

**v0.36.1-trackv2**（临时分支测试版，含 v0.37.0 世界栈总览）· Minecraft **26.3** · Fabric Loader **0.20.1** · Java **25**

## 能做什么

| 功能 | 状态 | 说明 |
|---|---|---|
| 世界与新一轮 | ✅ 可用 | `world` 固定是栈顶；旧世界是 `world/dimensions/samsara/stack_<n>` 自定义维度；出生点历史自动定义“当前轮”，不需要先注册周目；导入/排序/归档、操作时间线与连续撤销、快照导出/清理、多栈地图见 Web“世界栈”页 |
| 跨栈自动链 | ✅ 可用 | 玩家不需要 `world enter` 或管理员预先开启多世界：沿主世界/下界上下四个方向自动连续穿越相邻栈层；从上层下界虚空下坠时会从下层主世界高空落下并保持进入虚空时的动量（默认缓降，可用配置关闭）；目标层启动时加载失败会自动重试并显示原因；死亡后回到所在层出生点 |
| 本体管理 | ✅ 可用 | Web 一级分栏“模组/插件”与“本体”；6 个服务器文件同页折叠显示，左侧导航跳到文件/分组/条目；配置项按类型渲染（分段按钮、数字/密码/URL/多行、中文说明），白名单/OP/封禁可从已知玩家选择并自动填时间；存档备份为可分支时间线，支持一键回滚到任意节点、下载/删除，恢复在停服后执行并自动保留当前 world；“文件位置”树也在本体→存档备份下，列出配置、世界栈备份、本体备份与缓存目录 |
| 同世界重置 | ✅ 可用 | 任意栈层可执行：保留圈地保护区块，倒流删除该层未保护区；排斥算法选新出生点（避开海洋/岩浆/陡坡/保护区），只传送当前在该层/上次在该层的玩家；栈顶更新世界重生点，旧栈层只改个人重生点 |
| 分组出生 | ✅ 可用 | 玩家按 3~5 人分组，围绕新出生中心分散；离线玩家上线后补传送 |
| 时间倒流 | ✅ 可用 | 未圈地区块按设定周期逐格恢复：近处慢放、远处按曲线退场，完成后备份、删除并重新生成 |
| 旗帜圈地 | ✅ 可用 | 图案定方向、图案颜色定距离；单面旗帜只生成射线，所有旗帜的射线汇总后才做全局“化线为面”，只有多面旗帜围出的闭合区域才进入保护；必须同时包含方向图案和至少一个图标/盾徽图案才会注册为圈地旗；距离可按图案颜色配置或在 Web 可视化预览 |
| 圈地范围配置 | ✅ 可用 | 独立“圈地范围”标签页：`claim-range.yml` 可设固定距离、16 种图案颜色各自的延伸距离、15 种图案的单位方向与单方向上限；固定/图案颜色模式切换后立即显隐对应距离表，左侧导航同步，新出现的行会高亮几秒；颜色用 4×4 浮窗色板（色块 + 名称 + 序号 + 距离），图案用带真实预览的 4 列网格；调试画布提供北/东/南/西分段朝向、朝向扇形/箭头、固定罗盘、滚轮连续缩放与空白拖拽平移；另有旗帜合成器，可叠多层图案、预览、生成 `/give` 命令并填入画布；保存后已有圈地立即重算 |
| 安全删除 | ✅ 可用 | 预览、备份、执行、报告；删除前把受影响 `.mca` 备份目录再压成整档 zip；全服级整档快照仍由 Web“存档备份”负责 |
| 活动记录 | ✅ 可用 | 静默记录登录、在线时长与本次会话的原版统计增量，供事后 Web 统计 |
| 玩家轨迹 | ✅ 可用 | 5Hz 采样位置/朝向/状态，按「世界 + 周目 + 日期」留档并按年龄几何简化；回放为原版人偶（Mannequin），支持多人同屏、攻击/交互即捕捉；`.evt` 侧车记录并还原 6 个可见装备槽、选中槽、攻击/使用动作、飞行类型与真实载具类型；回放与回看都会还原潜行/疾跑/游泳/飞行/骑乘/受伤/死亡姿态，创造飞行不再伪装成鞘翅；旧轨迹无事件时降级为空手并提示 |
| 回看模式 | ✅ 可用 | `/samsara track view` 只读回看任意时间段：倍速、时间窗、跟随/旁观/发光/名牌、暂停恢复、倒放、自动瞄准（死区平滑修正，可即时开关）、进度跳转；回看人偶始终不可交互，但旁观左键可进入人偶视角；观看者全程旁观，可在 32 格内自由活动，超出/人偶瞬移/换维度自动跟随；会话期间免伤，结束恢复观看者，不写轨迹/差异/截断点/存档/周目数据 |
| 回看控制 | ✅ 可用 | 聊天栏可点击控制条（倍速/暂停/继续/倒放/对齐/自瞄/拖动/±10s/±30s/25%/50%/75%/停止）；`拖动模式`用 A 后退、D 快进、空格暂停、Shift 加速（服务端读取，无需客户端模组；滚轮不可用）；`/samsara track list` 条目可点击自动填入命令；`/samsara help` 与 `/samsara` 等价 |
| 可点击指令 | ✅ 可用 | `/samsara` 帮助、`world info`、`spawn`、`claim info`、`where` 等只读命令点击即执行；`reset same/new`、`debug *`、`perm set` 等危险命令点击只填入、不执行 |
| Tab 补全 | ✅ 可用 | 玩家名、`cycleN`、回看开始时刻/参数/时长/倍速、周目模式、权限路径与等级、区块坐标、布尔开关等；补全项带说明，不按键读盘；候选按命令叶子的权限过滤，`disabled` 或权限不足的 literal 不再出现 |
| 聊天栏补全 | ✅ 可用 | 输入不完整或拼错的 samsara 指令并回车时，不弹原版错误，而是在聊天栏列出可选项；一行多个、点击只填入聊天框；与 Tab 补全同源并共用权限过滤，另含拼写近似（`/seasn` → `season`）；只接管 samsara 自己的指令，不影响其他模组 |
| 补全交互增强 | ✅ 可用 | 有执行器的节点提供 `[展开子命令]`；点击候选自动补分隔符并打开下一层候选（普通参数补空格，玩家名单等逗号列表补逗号）；候选超过单页时可点击 `[上一页] [下一页]`，翻页不改变聊天输入、不执行命令 |
| 配置/数据分层 | ✅ 可用 | 配置留在 `config/samsara/`；周目、圈地、轨迹、倒流、回看等世界数据随存档走；身份/认证等全局数据默认也随存档，可配置为服务器级并双向迁移 |
| YAML 配置 | ✅ 可用 | 配置改为带注释的 YAML；首次启动生成全部默认项，旧 JSON 配置自动迁移并保留 `.legacy` 备份；保存原子写并保留 `.bak` |
| 本地 Web 配置管理 | ✅ 可用 | 仅监听本机的单页控制台：身份组 / 配置 / 圈地范围 / 地图 / 输出格式 / 权限六个同级标签页共用一个会话；未填写 token 时显示骨架屏并用置顶模态框提示输入，连接后 header 不再显示 token；左侧全局导航随内容自动生成；各标签共用一个固定“重新读取 / 保存”操作栏；切换标签保留滚动位置，点击导航会先滚动内部列表再对齐到导航顶部，右下角可快速置顶 |
| 配置页体验 | ✅ 可用 | 输入框宽度受控、说明文字不再被挤成窄列；缺失项直接显示真实默认值并在保存时写回；长列表等大数据默认折叠；粒子配置用 MC 26.3 原版粒子贴图预览，昼间用 MC 白天天空配色、夜间黑色，点击画布会在鼠标处生成粒子 |
| 输出格式 | ✅ 可用 | “手动改写”是一块文本画布：首行前缀是普通可编辑文字，不自动插入三角箭头；可用“自动续行前缀”开关决定游戏内是否自动加 `  ▸ `；变量/按钮是不可改字的原子标签且允许重复，按钮标签可单独编辑；标签可退格或点悬停 × 删除；支持 Ctrl+Z / Ctrl+Y；画布换行原样进入游戏 |
| 权限树 | ✅ 可用 | 命令路径与权限检查点合并成一棵树，关闭树干自动级联关闭树枝与叶子；叶子实际等级取整条路径的最高等级，树枝之间互不影响；标签页与统计区显示命令路径/自定义规则数量；`permissions.yml` 不再在配置页重复出现，owner 名单在权限页右侧维护，添加项固定在列表顶部 |
| 身份组卡片 | ✅ 可用 | 每个组是一张卡片，未进组候选按“正版 UUID / 离线 UUID / 数据 UUID”分区；拖拽到“数据 / 正版 / 离线”区域即可组合，导航显示组名和玩家名。身份组按 UUID 匹配，正版槽只收正版 UUID、离线槽只收离线 UUID；正版/离线入口全局唯一，data UUID 可复制到多个组共享同一份玩家数据、也可清空或删除；账号派生 data 显示“正版数据 / 离线数据”，随机生成显示“空白 data”；已有组改 data 会自动弹出重绑确认。候选池支持搜索，默认隐藏 `probe*`/`DSH_*`/测试名/`玩家-xxxxxxxx` 占位名，三个池子可折叠；按名称相似度给出“可能同一人”建议，点击才创建草稿组；每个候选有“→组”弹窗，长列表不拖拽也能入组，拖拽靠近视口边缘自动滚动 |
| UUID 解析 | ✅ 可用 | 输入玩家名自动计算离线 UUID，并尝试从 Mojang 获取正版 UUID；已知 UUID 实时显示玩家名；身份组、配置、圈地范围、输出、权限共用同一次 token 连接 |
| 关服提示 | ✅ 可用 | `/samsara restart [秒]` 默认 10 秒倒计时，结束后正常停服并保存；退出界面向在线玩家显示“服务器已关闭，请稍后重新连接”。外部 `/stop` 不倒数但仍发退出提示；强杀/崩溃无法发送 |
| 权限 | ✅ 可用 | 四级权限，命令所需等级可配置，支持 owner 名单 |
| 位置查询 | ✅ 可用 | `/samsara where` 查看自己的维度与坐标（可带区块、朝向），`where broadcast` 广播全服；命令启用与输出字段在 `config/samsara/commands.yml` 配置 |
| TPA 传送 | ✅ 可用 | `/tpa`、`/tpahere` 发起请求，`/tpaccept`、`/tpdeny`、`/tpcancel` 处理；默认 60 秒过期、每人同时只有 1 个请求、仅同维度；请求消息带 `[同意] [拒绝]` / `[取消请求]` 可点击按钮 |
| 命令短别名 | ✅ 可用 | `/season`、`/claim`、`/where`、`/version`、`/track`、`/tpa` 系列等；被其他模组占用时自动让位，只保留 `/samsara` 全名 |
| 新世界与跨世界传送 | ✅ 可用 | `reset new [种子] [levelType] [archiveData]` 把当前 world 压入 `stack_<n>` 维度，新 world 用独立种子/生成器（flat/amplified 等）；`archiveData=true` 只把旧 `data/minecraft` 归档到旧栈层，运行期所有栈共享当前 data；旧世界原位保留；主世界/下界虚空与顶部阈值可连续穿越栈层，栈底下界虚空保留原版死亡；多个玩家可同时待在不同栈 |
| 全员同意开新周目 | ✅ 可用 | 无管理员且在线 >1 人时，任何玩家可 `/samsara season advance [same\|new]` 发起；发起者自动同意，当前在线与新加入玩家都需 `/samsara season agree`；全员同意后执行一次同世界重置或新世界入栈；48 小时内未达成自动过期，重启后仍按发起时间计算；发起者可用 `/samsara season cancel` 撤回，管理员/控制台可取消；管理员在线时请直接 `/samsara reset same\|new` |
| 身份组 | ✅ 可用 | 把正版/离线/历史账号映射到同一个 data UUID；默认关闭，关闭时不解析、不同步；组由本地 Web 的“身份组”标签页以卡片方式维护，不提供注册/登录/密码 |
| 账号切换同步 | ✅ 可用 | 同账号重连不同步；正版 ↔ 离线账号切换时同步背包/位置/进度/统计；失败保留 journal、`.bak` 与源数据 |
| 宠物多主人 | ✅ 可用 | 保留原版主主人，额外主人写入 `samsara:owners`；所有主人可交互/坐下/染色/喂食/繁殖；跟随按主主人→最后手持驯服物品→最近在线主人 |
| 开场流程（Fabric） | ✅ 可用 | 新一轮开场、分组与传送由 Fabric 服务端事件/代码实现；`reset new` 首次生成新世界后自动计算出生点、分组并迁移；数据包不依赖 |
| Web 地图 | ✅ 可用 | “地图”标签按 v0.24 栈清单分组显示栈层，每个栈层下再选主世界/下界/末地；按对应栈层的 region 生成地表底图，叠加该层圈地保护区块、边界与旗帜；支持拖动、0.0625~16 格/像素缩放、定位全部圈地、栈层/维度导航和旗帜详情；选中旗帜显示单旗射线与右上角半透明 HUD；出生点历史按栈层显示独立标记，点击可复制传送命令（下界按主世界 /8 推算并标注）；新增“世界栈总览”：每栈主世界在上、下界在下、末地在右侧并排，栈间与主世界/下界之间留虚空/高空缝隙，面板用真实 region 缩略图 + 维度色边框，在线玩家按栈/维度显示并每 2 秒刷新，点击玩家复制 TP 命令、点击面板进入详细地图；地形 tile 使用内存热缓存 + `world/samsara/web-map-cache/` 磁盘缓存，region 变化自动失效、按 LRU 限额淘汰，缓存目录可安全删除；圈地范围保存或热重载后，保护区块缓存也会按配置指纹失效并在下次打开地图时重新拉取；只读，不加载区块、不写世界数据，首次按圈地范围取景 |
| 世界栈管理 | ✅ 可用 | Web 新增“世界栈”页：列出栈层 index/id/栈顶/世界名/存档创建与最后游玩时间/版本/种子/出生点/历史/维度/数据大小/来源；从服务器本地 world 目录导入到栈底、两层之间或栈顶，默认复制且源目录只读；**支持连续确认多个导入，按队列在一次重启内依次执行，队列项可取消**；导入/归档有预览、磁盘空间与玩家冲突检查、排队任务、结果报告和失败回滚说明；排序列表按**栈顶→栈底**显示，支持拖动/上下移动并在保存前预览，只改逻辑顺序，不重命名 `stack_<n>` 目录；把旧栈层拖到栈顶会交换 world 数据并在重启时生效，失败回滚；归档面板直接列出可归档层，归档先移动到 `backups/samsara/world-stack-archive/` 备份，不直接删除；操作时间线顶部显示待执行任务；导入路径限制在服务器根或 `web.yml` 的 `importRoots`，拒绝旧布局、正在使用、世界栈存档，以及缺 `data/minecraft/world_gen_settings.dat`、快照版本或比服务器更新的世界；`world-stack-backup` 按 `backupKeep`（默认 5）只保留最新几份，归档永不自动删除 |

## 常用命令

| 想做什么 | 命令 |
|---|---|
| 查看身份组 | `/samsara identity status`（短别名 `/identity`） |
| 管理身份组 | 本地 Web 控制台的“身份组”标签页；游戏内只读诊断 `/samsara debug identity map|preview|reload|audit`（owner） |
| 看当前世界/轮次/出生点 | `/samsara world info`、`/samsara spawn`、`/samsara spawn history` |
| 看圈地 | `/samsara claim info`、`/samsara claim boundary` |
| 同世界重置 | `/samsara reset same`（在玩家当前栈层执行；倒流 + 删未保护区 + 排斥点重生；二次确认） |
| 无管理员开新周目 | `/samsara season advance [same\|new]` 发起 → 在线玩家 `/samsara season agree` → `/samsara season vote-status` 查看名单与剩余时间；发起者/管理员可 `/samsara season cancel`；48 小时未全员同意自动过期 |
| 新世界入栈 | `/samsara reset new [种子] [normal\|flat\|amplified\|...] [true\|false]`（第三个参数 `archiveData` 只归档旧 data；二次确认） |
| 看/切换世界栈 | `/samsara world list`、`/samsara world info`；管理员 `/samsara world enter <世界名>`、`/samsara world leave`（直接传送到栈维度，不再停服） |
| 管理/调试 | `/samsara debug ...`（owner；圈地、倒流、轨迹、配置、测试数据） |
| 查看补全候选 | `/samsara debug completion <指令片段>`（owner；只打印候选，便于排查补全） |
| 回放玩家轨迹 | `/samsara debug track replay <监控目标> <开始时刻> [倍速] [周目]` · `track stop [监控目标\\|all]` · `track status` |
| 回看历史轨迹 | `/samsara track view <监控目标> <开始时间> [--speed 4 --duration 30m --follow --aim --equipment-drop=on\|off]` · `view stop/status/pause/resume/align/seek/aim/scrub [观看者]` · `view inspect [观看者] [页]`（只读背包） · `view drop on\|off`（本次回看装备掉落） · `view ui [接收者\|broadcast]` · `track list <监控目标>`（短别名 `/track`） |
| 看自己的坐标/维度 | `/samsara where`；`/samsara where broadcast` 广播全服 |
| 传送到别人/让别人过来 | `/tpa <传送请求接收者>`、`/tpahere <传送请求接收者>`；对方 `/tpaccept` 或 `/tpdeny`；发起者 `/tpcancel` |
| 看版本 | `/samsara version`（别名 `/version`） |
| 关服/重启 | `/samsara restart [秒]`（默认 10 秒倒计时；退出界面显示“服务器已关闭，请稍后重新连接”） |

> 世界与出生点在 `/samsara world`、`/samsara spawn`、`/samsara reset`；调试与圈地管理在 `/samsara debug`。游戏内输入 `/samsara` 或 `/samsara help` 可看帮助（列表里的青色按钮点击即执行，黄色按钮点击只填入）。
> `reset new` 会修改 `server.properties` 的 `level-seed`/`level-type` 并停服，**必须由启动脚本重新开服**后才会生成新栈顶；`world enter/leave` 直接传送到栈维度，不停服。栈清单在 `world/samsara/stack.json`，旧栈元数据在 `world/samsara/stack/stack_<n>/`。
> **data/minecraft 语义**：v0.24 采用“归档”而非运行期隔离——`archiveData=true` 只把旧 `data/minecraft` 复制/移动到旧栈层归档，新栈顶从新数据开始；运行期所有栈共享当前 `world/data/minecraft`。升级 MC/更换存档布局时必须重验 `LevelStorageAccess`、`ServerLevel` 与 `MinecraftServer.levels` 字段。
> **旧布局迁移**：服务器根下已有 `world` + `world_s1` + `world_s2`（world 为栈底）时，启动会自动迁移为 `world=栈顶`、旧层 `stack_0/stack_1` 维度；玩家数据合并到 `world/players`，claims/diff/track 留在各自栈数据根，旧目录内容进入 `legacy-layout.migrated-*` 或栈层 `legacy-root/`，不复制区块。
> 所有玩家名、世界、时长、回看参数、权限路径/等级都支持 **Tab 补全**；输入不完整时按回车，也会在聊天栏列出可点击候选（一行多个，点击只填入）。回看时段列表与帮助里的危险命令只填入命令，不会直接执行。

## 安装与构建

需要 **JDK 25**；Gradle wrapper 已内含。先让 `JAVA_HOME` 指向 JDK 25，再构建：

```bat
cd mod
set JAVA_HOME=C:\Program Files\Java\jdk-25
gradlew.bat build
```

Linux/macOS 用 `./gradlew build`。产物是 `mod/build/libs/samsara-<版本>.jar`，放进服务器 `mods/`。

| 组件 | 版本 |
|---|---|
| Minecraft | 26.3 |
| Fabric Loader | 0.20.1 |
| Fabric API | 0.165.0+26.3 |
| Java | 25 |
| Gradle / Loom | 9.5.1 / 1.17 |

> 26.2 起使用 Mojang 官方映射，构建脚本不需要 yarn 映射；26.3 沿用同一套构建链。

## 自动化验收

Web 冒烟 E2E 使用系统 Edge/Chrome 的 headless + CDP，零 npm 依赖：

```powershell
# 测试服已在运行
node tools/web-e2e.mjs --base http://127.0.0.1:8730 --token testtoken

# 或自动启动/停止测试服

```

覆盖：token 连接、6 个服务器文件同页/分组/70 条目/中文说明、折叠、搜索、玩家选择、备份时间线与回滚预览、身份组/输出/权限/配置页布尔按钮、重复 id、未捕获脚本错误。退出码 0 为通过；默认不保存配置、不创建或恢复备份。

## 加载方式

模组按“服务端入口 + 客户端也加载”的方式声明：

- **专用服务器**：全功能；
- **客户端 + 单人存档**：单人内置服务器启动时同样加载；
- **客户端 + 连别人服务器**：不执行服务端逻辑，零副作用。

> **不要改成仅服务端**：那样客户端（含单人存档）会把模组过滤掉，单人玩法直接不可用。

## 数据放在哪

模组把数据分成四层：**配置**留在服务器级目录，**世界数据**与**身份运行时数据**随存档走，**全局数据**默认也随存档。

| 层 | 默认位置 | 内容 | 随存档 |
|---|---|---|---|
| 配置 | `config/samsara/*.yml` | 命令开关、权限、圈地粒子、圈地范围、存储覆盖、Web、身份组 `identity.yml`、输出模板 `output.yml` | 否 |
| 世界数据 | `world/samsara/` | 栈清单 `stack.json`、出生点历史、圈地、倒流、轨迹、回看、备份、活动、审计；旧栈元数据在 `world/samsara/stack/stack_<n>/` | 是 |
| 世界维度 | `world/dimensions/` | 栈顶 `minecraft/{overworld,the_nether,the_end}`；旧栈 `samsara/stack_<n>/{...}` | 是 |
| 身份运行时数据 | `<存档根>/samsara/identity/` | `state.json`、按 data UUID 存玩家数据、journal、archive、身份审计 | 是（固定随主存档） |
| 全局数据 | `<存档根>/samsara/global/`（默认）或服务器级 | 跨世界审计等；`globalFollowWorld` 可改位置 | 默认是 |

- `<存档根>` 在专用服务器是 `world/`，单人存档是 `saves/<存档名>/`。`world` 固定是栈顶；旧栈层是它内部的 `dimensions/samsara/stack_<n>`，所以备份整个 `world` 就包含全部栈层。
- 地图地形缓存 `world/samsara/web-map-cache/` 是派生数据，可随时删除；删除后地图重新渲染，不影响圈地/轨迹/差异数据。
- 世界栈导入/归档的待执行任务在 `world/samsara/pending-*.json`，重启时由模组在世界打开前执行；归档备份在**服务器根目录**下的 `backups/samsara/world-stack-archive/`，导入/提升栈顶备份在 `backups/samsara/world-stack-backup/`，不跟随存档；任务报告在 `world/samsara/world-stack-jobs/`。
- `<服务器根>/backups/samsara/` **只放服务器级备份**（世界栈归档/导入备份、本体存档备份、本体配置备份），不是运行时数据；不用这些备份时不会创建。旧版本 `<服务器根>/samsara/` 下的备份启动时会自动迁移到这里；v0.23 的 `world-stack.json` 缓存已废弃，可安全删除。
- **运行时数据仍建议留在 `world/samsara/`**：栈层、圈地、轨迹、差异都跟存档绑定，复制/恢复某个世界时必须一起走；Web 本体备份和整个服务器备份都会包含它，因此不需要为了备份把数据搬到服务器根目录。
- Web“世界栈”页的“文件位置”按当前服务器动态列出配置、世界数据、地图缓存、任务报告和服务器级备份的目录树，并支持复制绝对路径。
- **存档备份会包含 `samsara/` 世界数据**（轨迹与倒流记录可能较大）；配置不随存档复制。
- **身份组配置**固定在 `config/samsara/identity.yml`，不随存档走；身份运行时数据固定在 `<存档根>/samsara/identity/`，随主存档复制/备份，不随世界栈或 `globalFollowWorld` 切换。
- 只转移存档时 `identity/playerdata` 会一起走，但 `identity.yml` 不会；完整迁移请同时复制它，或使用 Web 导出/导入。
- 旧版认证数据（`identity.json`、`auth.yml`）在首次启动时迁移/归档到 `identity/archive/`，原文件保留；认证能力已退役，身份安全交给其他认证模组。
- 全局数据可用 `storage.yml` 的 `globalFollowWorld`（默认 `true`）改为服务器级 `<服务器根>/samsara/global/`；切换时程序自动双向迁移。
- 旧版全部放在 `config/samsara/` 的数据，首次启动会迁移一次；旧目录改名为 `config/samsara.legacy` 保留备份，确认无误后可手动删除。
- 旧路径说明以[《设计规范》](docs/设计规范.md)的〈文件布局：配置、世界数据与备份位置〉为准。

命令功能开关在 `config/samsara/commands.yml`：`where.enabled` 控制是否启用 `/samsara where`，`where.broadcast` 控制是否允许广播，`where.broadcastCooldownSeconds` 是广播冷却（0=不限），`where.showCoordinates/showDimension/showChunk/showFacing` 控制输出字段；`tpa.enabled` 控制 TPA 系列，`tpa.requestTimeoutSeconds` 是请求有效期（默认 60），`tpa.crossDimension` 控制是否允许跨维度；`view.protectViewer` 控制回看时是否免伤，`view.freeRoamRadius` 是回看时允许自由活动的半径（默认 32 格）；`completion.chatList` 控制未完成指令是否在聊天栏列出候选，`completion.fuzzy` 控制拼写近似，`completion.maxItems` 控制单页最多展示多少项（超出可翻页）；`shutdown.countdownSeconds` 控制 `/samsara restart` 默认倒计时；`output.autoContinuePrefix` 控制游戏内续行是否自动加 `  ▸ ` 前缀。改完执行 `/samsara debug reload` 生效，无需重启；也可以打开本地 Web 面板编辑。

圈地保护范围在 `config/samsara/claim-range.yml`：`mode` 可选 `dye`（按图案颜色，默认保持旧行为）或 `fixed`（所有图案颜色同一距离）；`fixedDistance` 是固定距离；`colorDistances` 是 16 种图案颜色各自的延伸距离（单位：区块）；`patternDirections` 为 15 种旗帜图案分别指定单位长度上的方向（north/northeast/east/...，图案只定方向，图案颜色只定长度，旗面底色只影响外观）；`maxDistance` 是单方向上限。保存后已有圈地会立即按新范围重建白名单。Web 的“圈地范围”标签页切换模式后条件项立即显隐；颜色用 4×4 浮窗色板（每格显示颜色名、序号与该颜色在当前模式下的距离），图案用 4 列预览网格；调试画布可切换北/东/南/西朝向、用滚轮以光标为中心缩放、在空白处拖拽平移，双击重置。单面旗帜只画射线，多面旗帜的射线在全局闭合后才填充内部；服务端保护区块与 Web 预览使用同一套规则。

本地 Web 面板默认**关闭**；在 `config/samsara/web.yml` 勾选 `enabled` 后才会监听 `127.0.0.1:8720`，首次启动会在控制台打印访问令牌。用浏览器打开后只需在弹窗里填入一次令牌，连接成功后 header 不再显示 token；面板不会改世界数据，也不提供公网监听。开启时请只在本机使用，不要把端口暴露到公网。“圈地范围”是独立标签页，用图案颜色色块编辑距离并实时画出保护形状。“身份组”是独立页面：可增删改身份组、设置 data/premium/offline、从在线玩家或 usercache 选 UUID、预览圈地/玩家数据/轨迹/活动影响；已有组修改 data UUID 时会自动弹出重绑确认，默认拒绝覆盖已有数据。

“输出格式”页把手动改写和渲染预览分成两个并排区域：左侧选消息，中间是一个类似文本框的 Token 画布，文本、变量、按钮和首行前缀都可以在画布内上下左右拖拽排序；文本与 `[周目管理] ▸ ` 前缀可直接编辑。右侧实时显示服务端渲染结果。变量只能从后端面板拖入，手写 `{player}` 只是普通文字；按钮命令固定，只能移动、删除或改显示标签。保存后自动热重载，`output.yml` 保存结构化片段而不是纯字符串模板。默认模板逐字保持升级前输出；点击“恢复默认”回到系统默认。

“权限”页按真实命令树的层级展示权限：每个节点可单独设置 `user/op/owner/config` 或恢复继承；取消“启用”会关闭该节点及其所有后代，重新启用后各节点恢复原来的等级。叶子的实际所需等级取整条路径上的最高等级，因此关闭或提高树枝权限会同时约束该树枝下的所有叶子，但不会影响其他树枝。

活动记录按天保存，只写不读：登录、在线时长，以及本次会话的移动、挖掘、使用、击杀、交易等原版统计增量。没有 tick 轮询，也不提供游戏内查询命令；字段与开销见[《设计规范》](docs/设计规范.md)的〈活动记录：静默采集约定〉。

倒流记录按维度保存在常开窗口 `diff/live/minecraft/overworld…`（主世界、下界、末地互不混写），倒流开始时冻结为 `diff/cycle<周目id>/`；旧版 `diff/current`、`diff/s<id>`、`diff/<窗口>/<世界>/` 与无世界层记录会在启动时自动迁入新布局，记录在运行中与停服时落盘，服务器重启不会丢掉最近一段改动。

玩家轨迹按「周目 + 日期」保存在 `track/cycle<周目id>/<日期>/<uuid>.bin`，装备/动作/飞行/载具/可选背包写在同目录 `<uuid>.evt`；越老的记录按 `track.retention` 选择 adaptive（1/4/16/64/256 天档位，默认）、keepAll 或 curve 做几何简化，并保留每天至少一份骨架点；回放用原版人偶（Mannequin，客户端无需安装模组、带玩家皮肤），支持多人同屏。人偶被玩家攻击/交互后会停止回放并变成普通实体；该玩家该周目从捕捉时刻起的轨迹不再回放（磁盘记录保留，截断点写在 `track/cutoffs.json`）。捕捉不保护所在区块：留在会被删的区块里的人偶会和区块一起消失，提前运到安全区块才能活到下一周目。
